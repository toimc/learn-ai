# daydayup：项目自我成长循环

把「多 agent 团队评审 + 知识沉淀」做成可周期运行的机制。产出只有两类：**评审日报**（`docs/daydayup/`）与**知识资产建议**（规则/技能/AGENTS.md 的 diff 建议）。本技能不直接修业务代码。

## 运行档位

| 档位 | 触发 | 行为 |
|---|---|---|
| 完整档 | 手动 `/daydayup`；用户说"跑一期天天向上 / 项目巡检" | 三轴并行 subagent 审查 + 对抗复核 + 完整日报 |
| 定时档 | 夜间定时任务（23:17 durable cron） | 先做第 0 步增量探测：变更面仅 docs/** 与 .claude/** 且无未消化发现 → 写静默期日报收场；否则升级为完整档 |

## 流程（完整档六步）

### 0. 快照与增量探测

- `git log --oneline <上期HEAD>..HEAD` + `git status`，确定本期变更面（首次运行取 `git log --oneline -30`）
- 读 `docs/daydayup/README.md` 索引确定期数 N 与上期行动清单；上期行动项逐条标 done / 逾期 / 放弃（带验证命令的跑一遍判定）
- 无变更面的轴直接标"本期无变更，沿用上期结论"，不重扫

### 1. 三轴并行审查

一条消息并行发出 3 个 `general-purpose` subagent，**只读审查**，范围优先限在上期以来的变更面：

- **arch 轴（架构与代码健康）**：红线违反（core 零依赖 / workspace:* / ChatAdapter 解耦）、死代码、TODO/FIXME、超长文件、跨包重复实现；抽查 `.claude/rules/` 三条规则的落地情况
- **quality 轴（质量与流程）**：`__tests__/` 镜像缺口、文档失同步（docs 页面 vs 源码 API）、CI 与脚本死角、依赖健康、覆盖率门禁现实
- **curator 轴（知识沉淀）**：结构保鲜（AGENTS.md 包/skills 清单 vs `git ls-files`、全部引用路径存在性）、双轨漂移对账（diff `.claude/` 与 `.codex/` 同名文件）、规则承诺 vs 配置现实、memory 对账（描述与现状不符的标过期；满足「项目特有 + 高频踩 + 可写成可执行检查项」三标准但 rules 未覆盖的列为升级候选）

每个 subagent 的 prompt 必须带三条纪律：全程只读；证据必须落到 `文件:行号`，无证据标【推测】；硬预算（超限中止并在报告注明耗尽于第几步）。

### 2. 对抗复核（主线）

- 逐条过三路发现：去重、降级无证据项、与历史指纹比对（`文件路径 + 结论` 哈希，重复发现不重复报告）
- 有争议的发现写入「讨论与复核」一节，记录裁决理由
- 发现与结论分离：subagent 原始发现进日报附录（`<details>` 折叠），主文只放复核后的结论

### 3. 沉淀决策（人工闸门）

- **直接落地**（低风险知识资产）：日报本身、`docs/daydayup/README.md` 索引行
- **只出建议 diff、等用户确认**（行为契约，夜间一律不自动改）：`.claude/rules/*` 新增或修改、AGENTS.md 实质改写、新 skill、memory → rules 升级
- 夜间无人值守额外红线：禁止改 `packages/*/src` 业务代码、禁止发版、禁止 push

### 4. 写日报

`docs/daydayup/YYYY-MM-DD-第N期.md`，结构按下方模板。头部记录当期 HEAD，作为下期增量基线。同日重跑幂等：先查当日文件是否已存在，存在则修订而非新开一期。

### 5. 更新索引

`docs/daydayup/README.md` 追加一行：`| N | 日期 | 一句话主题 | 触发 | 状态 |`。

### 6. 提交

中文 Conventional Commits（scope 用 `daydayup`），**明确文件清单**（严禁 `git add -A`，多会话并行会卷入别人的改动），不 push。注意 `git add` 与 `git commit` 拆成两条命令（复合命令会被 PreToolUse hook 整条拦截）。

## 防空转纪律（硬约束）

- 增量短路：某轴无变更面 → 该轴标"本期无变更"，不重扫
- 静默期收场：全轴零新发现 → 固定的短模板（上期回顾 + 指纹 + 一行"本期静默"），不凑数、不硬挖
- 指纹去重：重复发现不重复报告，连续 3 期未完成的行动项标僵尸并给处置（降级 / 删除 / 升级原因）
- 行动清单 ≤ 8 条且必须可执行、带验证命令
- 「不怕耗 token」≠「可以空转」：该全跑的全跑，无新发现就体面收场

## 日报模板

```markdown
---
期数: N
日期: YYYY-MM-DD
触发: manual | scheduled
基线: <上期HEAD> → <本期HEAD>
参与: arch / quality / curator + 主线复核
---
# 第 N 期 · YYYY-MM-DD · 一句话主题

## 快照（提交范围 / 变更热点）
## 本期发现（P0 / P1 / P2，带 file:line 证据）
## 讨论与复核（争议点的裁决与理由）
## 沉淀（本期直接落地的知识资产 + 待用户确认的建议 diff 清单）
## 行动清单（≤8 条：优先级 / 内容 / 验证命令）
## 下期关注
## 附录：三轴原始发现（<details> 折叠）
```
