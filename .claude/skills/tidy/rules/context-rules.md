# 上下文收敛规则（外置，仅 /tidy context 模式加载）

> 本文件不进常驻上下文。目标：把「只在特定任务时才需要的规范」从常驻面（CLAUDE.md / rules/*.md）迁移到对应 skill 的外置文件，任务触发才加载——未触发该任务的会话零 token 成本。

## 机制（为什么能省）

- CLAUDE.md 与 `.claude/rules/*.md`：**每会话全量注入**，每个字节每轮都要付费
- skill：只有 frontmatter `description`（约 2 行）进常驻 skill 列表；SKILL.md 与 `rules/` 子文件**触发时才 Read**
- 所以：高频、跨任务的行为约束留常驻；低频、任务型规范外置

## 审计流程

1. **收集常驻面**（逐个 `wc -c` 记录基线）：
   - 项目：`CLAUDE.md`、`.claude/rules/*.md`
   - 全局（用户要求时才审计）：`~/.claude/CLAUDE.md`、`~/.claude/rules/*.md`
2. **逐段三问分类**：
   - Q1 是否只在特定任务类型时相关？（如「测试临时文件规范」只在跑测试时相关）
   - Q2 是否已有 skill 承接，或值得为其建 skill？
   - Q3 删掉后普通会话行为是否退化？（编码规范/git 规范/安全红线 = 会退化，必须留）
3. **三类去向**：
   - 常驻必要：留原位（红线、跨任务约束、每次都要遵守的规范）
   - 任务型可外置：**剪切**到目标 skill 的 `rules/` 文件；原位置留一行指针
   - 过时冗余：直接删（引用不存在的文件、已被 git history 记录的一次性事实、重复段落）
4. **出迁移方案表**（先获用户确认再动手）：

   | 段落（文件:行） | 字节 | 去向 | 触发方式 | 预计节约/会话 |
   |---|---|---|---|---|

5. **执行迁移**：剪切正文 → 目标 skill rules 文件追加（带来源注释）→ 原位置留指针 → `wc -c` 复测

## 指针写法

原位置只留一行，让未来会话知道去哪找：

```markdown
<!-- 已外置：临时文件规范迁至 .claude/skills/tidy/rules/cleanup-rules.md，/tidy 时加载 -->
```

不要把外置内容的摘要留在原位——那等于没省。

## 红线

以下内容**永不外置**（任何会话都可能触发高危操作，必须常驻）：

- 文件操作安全（删除确认、高危命令禁令）
- git 高危操作禁令（reset --hard / push --force 等）
- 密钥/代理地址类（代码里要能直接引用到）
- 编码规范、提交规范等跨任务约束

## 度量与报告

- 迁移前后各文件 `wc -c` 对比，合计差额
- token 粗估：中文 ≈ 1.6–1.8 字符/token，英文/代码 ≈ 3.5–4 字符/token
- 报告格式：`常驻上下文 -<N> 字节 ≈ -<M> token/会话（每次会话均省）`
