# 主题系统重构 + 主题配置器（Theme Builder）设计 spec

> 日期：2026-08-13 ｜ 分支：`feat/theme-system-builder`（从 `dev` 开）
> 状态：设计已获用户批准。命名策略 = **N1（务实收敛，保留 `--ai-chat-color-*` 语义前缀，不触碰 300+ 处既有引用）**。
> 本文是后台实施团队的唯一蓝图，**照此转录实现**，不要自由发挥架构。

## 0. 决策记录

| 项 | 决定 |
|----|------|
| 命名收敛 | N1：保留既有 `--ai-chat-color-*` 语义命名，仅统一 sidebar 族 + 删旧兼容区 + 补 status 色 |
| 默认主题 | **亮色默认**：`:root` = 亮色完整默认；`[data-theme='dark']` 仅翻转语义层 |
| 三层令牌 | 原始(Primitive) → 语义(Semantic) → 组件(Component) |
| 配置范围 | **全部令牌**（原始/语义/组件三层，~45 个变量均可视化编辑） |
| 导出格式 | **CSS 覆盖文件**（`:root{...}` + `[data-theme='dark']{...}`），使用方 import 即覆盖 |
| 页面位置 | VitePress 文档新页面 `docs/theme-builder.md`（自定义 layout `ThemeBuilderPage`） |
| 事实来源 | 方案 A：`tokens-meta.ts` 类型化目录为事实来源，`tokens.css` 手写，靠对账测试防漂移 |

## 1. 范围与非目标

**做**：tokens.css 三层重构（亮色默认）、`tokens-meta.ts` 目录、`presets.ts`、`useTheme`/`useThemePreset`、`Conversation` 主题 Props、PlaygroundDemo 迁移、ThemeBuilder 配置器页面（预览/保存/导入/导出）、文档页与导航、测试。

**不做**：不把 `--ai-chat-color-*` 改名为 `--ai-chat-*`（N1）；不重构未被要求的组件；不引入 codegen 构建步骤；不做服务端主题。

  derived?: boolean

  ref?: string

## 5. `packages/vue/src/composables/useTheme.ts`

模块级单例；补 localStorage 持久化 + 自动写 `document.documentElement` 的 `data-theme`。注意 SSR 安全（VitePress 构建）：所有 `window`/`document`/`localStorage` 访问需在 `onMounted` 或 `typeof window` 守卫内。

```ts
import { ref, computed, watch, onMounted } from 'vue'

export type ThemeMode = 'light' | 'dark' | 'system'
export type ResolvedTheme = 'light' | 'dark'

const STORAGE_KEY = 'ai-chat-theme'

// 模块级单例状态
const theme = ref<ThemeMode>('system')
const systemDark = ref(false)
let initialized = false
let mql: MediaQueryList | null = null

function resolve(t: ThemeMode): ResolvedTheme {
  return t === 'system' ? (systemDark.value ? 'dark' : 'light') : t
}

export const resolvedTheme = computed<ResolvedTheme>(() => resolve(theme.value))

function onSystemChange(e: MediaQueryListEvent) {
  systemDark.value = e.matches
}

function init() {
  if (initialized || typeof window === 'undefined') return
  initialized = true
  // 读持久化
  const saved = localStorage.getItem(STORAGE_KEY) as ThemeMode | null
  if (saved) theme.value = saved
  mql = window.matchMedia('(prefers-color-scheme: dark)')
  systemDark.value = mql.matches
  mql.addEventListener('change', onSystemChange)
}

// 应用 + 持久化
if (typeof window !== 'undefined') {
  watch(
    resolvedTheme,
    (val) => {
      document.documentElement.setAttribute('data-theme', val)
    },
    { immediate: true },
  )
  watch(theme, (val) => {
    localStorage.setItem(STORAGE_KEY, val)
  })
}

export function useTheme() {
  onMounted(init)
  const setTheme = (t: ThemeMode) => {
    theme.value = t
  }
  const toggleTheme = () => {
    theme.value = resolvedTheme.value === 'dark' ? 'light' : 'dark'
  }
  return { theme, resolvedTheme, setTheme, toggleTheme }
}
```

> 首屏防闪：在 `docs/index.md`（或 VitePress 的 `config.head`）注入一小段内联脚本，同步读 localStorage 设 `data-theme`。由 docs 步骤实现：在 `.vitepress/config.ts` 的 `head` 加入一段 inline script（见 §13）。

## 6. `packages/vue/src/composables/useThemePreset.ts`

把预设 + 自定义变量以 inline style 应用到容器（inline style 优先级最高）。

```ts
import { watch, onMounted, type Ref } from 'vue'
import { presets, type PresetKey } from '../theme/presets'

export function useThemePreset(
  containerRef: Ref<HTMLElement | undefined>,
  preset: Ref<PresetKey | undefined>,
  customVars: Ref<Record<string, string> | undefined>,
) {
  function apply() {
    const el = containerRef.value
    if (!el) return
    // 仅清预设/自定义相关的原始层变量，避免清空宿主 inline style
    const keys = new Set<string>()
    if (preset.value) Object.keys(presets[preset.value].vars).forEach((k) => keys.add(k))
    if (customVars.value) Object.keys(customVars.value).forEach((k) => keys.add(k))
    keys.forEach((k) => el.style.removeProperty(k))
    const p = presets[preset.value || 'default']
    if (p) for (const [k, v] of Object.entries(p.vars)) el.style.setProperty(k, v)
    if (customVars.value)
      for (const [k, v] of Object.entries(customVars.value)) el.style.setProperty(k, v)
  }
  onMounted(apply)
  watch([preset, customVars], apply, { deep: true })
}
```

## 10. `packages/playground/src/components/ThemeBuilder.vue` —— 配置器（核心 UI）

**职责**：读取 `tokensMeta` 渲染全部令牌的可视化编辑控件；实时预览；明暗编辑切换；保存(localStorage)/导入/导出(CSS)。

### 10.1 数据模型（组件内）
```ts
// 当前编辑值：每个 token 的 light/dark 覆盖（仅存被编辑过的）

```

### 10.2 渲染规则（按 group 折叠分组，按 layer 顺序：原始→语义→组件）
- **过滤**：`search` 对 `key`/`label`/`group` 模糊匹配。
- **控件类型**：
  - `color` 且 **非 derived** → `<input type="color">` + hex 文本框；暗色编辑模式下对有 `dark` 的 token 出现第二组控件。
  - `color` 且 **derived** → 只读：色块（解析后的颜色，见下）+ 文案"派生自 {ref}"，不可编辑。
  - `size` → 数字框 + 滑块(min..max)，单位 `unit`。
  - `duration` → 数字框（单位 s）。
  - `font` → 文本框。
  - `text` → 文本框（rgba/keyword/transparent 等）。
- **derived 解析色**：维护一个隐藏的"活根"元素，把当前所有 light/dark 值（默认 + overrides）作为 inline CSS 变量套上去，对 derived token 用 `getComputedStyle` 读出解析后的颜色显示色块。editMode=dark 时活根带 `data-theme="dark"`。

## 12. `buildThemeCss` 与 `buildOverridesFromCss` —— 纯函数

放 `packages/playground/src/components/theme-css.ts`（或 `@toimc/vue` 内导出，二选一；放 playground 更省事）。**必须有单测**。

```ts
import type { TokenMeta } from '@toimc/vue'

type Overrides = Record<string, { light?: string; dark?: string }>

/** 生成导出 CSS。includeAll=false 时仅导出与默认不同的令牌。 */
export function buildThemeCss(
  meta: TokenMeta[],
  overrides: Overrides,
  opts: { includeAll?: boolean } = {},
): string {
  const lightLines: string[] = []
  const darkLines: string[] = []
  for (const t of meta) {
    const ov = overrides[t.key]
    const curLight = ov?.light ?? t.light
    const curDark = ov?.dark ?? t.dark
    const lightChanged = ov?.light !== undefined && ov.light !== t.light
    const darkChanged = ov?.dark !== undefined && ov.dark !== (t.dark ?? t.light)
    if (opts.includeAll || lightChanged) lightLines.push(`  ${t.key}: ${curLight};`)
    if (curDark !== undefined && (opts.includeAll || darkChanged))
      darkLines.push(`  ${t.key}: ${curDark};`)
  }
  const blocks: string[] = ['/* ai-chat-ui custom theme — generated by Theme Builder */']
  if (lightLines.length) blocks.push(`:root {\n${lightLines.join('\n')}\n}`)
  if (darkLines.length) blocks.push(`[data-theme='dark'] {\n${darkLines.join('\n')}\n}`)
  return blocks.join('\n\n') + '\n'
}

/** 从导出的 CSS 文本解析回 overrides。 */
export function buildOverridesFromCss(css: string, meta: TokenMeta[]): Overrides {
  const ov: Overrides = {}
  const known = new Set(meta.map((m) => m.key))
  const parse = (block: string, mode: 'light' | 'dark') => {
    const re = /([\w-]+)\s*:\s*([^;]+);/g
    let m: RegExpExecArray | null
    while ((m = re.exec(block))) {
      const key = `--${m[1]}`
      if (!known.has(key)) continue
      ;(ov[key] ??= {})[mode] = m[2].trim()
    }
  }
  const root = css.match(/:root\s*\{([\s\S]*?)\}/)
  const dark = css.match(/\[data-theme=['"]?dark['"]?\]\s*\{([\s\S]*?)\}/)
  if (root) parse(root[1], 'light')
  if (dark) parse(dark[1], 'dark')
  return ov
}
```

## 18. ADR 增补（2026-08-15）

> 来源：样式隔离专项规格 [`docs/superpowers/spec/04-样式隔离与样式Rules-20260815.md`](../04-样式隔离与样式Rules-20260815.md)，本节增补以下决策，**不推翻**本文原有任何决策。

| # | 增补决策 | 说明 |
|---|----------|------|
| ADR-8 | `:root` 全局令牌决策**保留** | 仍不做组件根作用域迁移、不引入 Shadow DOM；在此基础上新增级联防护 |
| ADR-9 | 新增 **@layer 级联防护**：`ai-chat-base < ai-chat-tokens < ai-chat-components < ai-chat-animations` 四层，顺序在 `tokens.css` 顶部声明一次；全部库样式进层，宿主未分层样式天然覆盖库样式（覆盖无需 `!important`）；全局 `*` box-sizing reset 收敛为 `.ai-chat-window` 子树作用域并进 `ai-chat-base` 层 | 解决令牌与 reset 随入口注入宿主、无级联防护的污染问题（P1） |
| ADR-10 | **KaTeX CSS 改可选子路径导入**：从 `useMarkdownIt.ts` 移除模块级 `import 'katex/dist/katex.min.css'`，改为包 exports 子路径 `@toimc/markdown/katex.css`，宿主渲染公式时手动引入；不用公式的宿主省 ~25KB CSS + 全局数学字体下载 | 解决 katex.min.css 无法 opt-out 的隐式注入问题（P3） |
| ADR-11 | **useTheme 新增选项**：`target: 'html' \| 'component'`（默认 `'html'`，向后兼容）与 `persist: boolean`（默认 `true`）。`'component'` 模式下 `data-theme` 写组件根元素而非宿主 `<html>`，不碰宿主主题系统 | 解决模块加载即写宿主 `<html>` 与 `localStorage`、与宿主自有主题系统冲突的问题（P2） |

沉淀的项目级样式纪律见 [`.claude/rules/style-isolation.md`](../../.claude/rules/style-isolation.md)。
