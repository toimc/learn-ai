# 消息列表响应式布局与 A/B 对比组件需求

- 日期：2026-08-13
- 分支：`feat/message-layout-comparison`（基于 `dev`）
- 状态：待复核

## 1. 背景与目标

Playground 当前消息列表为「头像 + 正文」全宽同行布局，用户与 AI 消息均在左侧，无对齐差异；输入区固定 768px 限宽，移动端体验未优化；缺少用于收集用户偏好的对比展示能力。本次在 `@ai-chat/vue` 公共库内完成三件事：

1. **消息列表响应式布局升级**：支持 IM 式左右分列与统一对齐两种模式可切换，宽屏下消息区更宽。
2. **新增 `ComparisonMessage` 组件**：A/B 候选回复双列对比，每列底部各一个「我更喜欢这个回复」按钮，收集用户偏好。
3. **新增 `useLayoutConfig` hook**：把响应式宽度等布局配置结构化映射到主题 CSS 变量，并注册进 `tokens-meta` 供 ThemeBuilder 可视化配置。

### 非目标

- 不改动 `@ai-chat/core` 的 `Message` / `StreamChunk` 类型（`ComparisonMessage` 走独立 props，后端无关）。
- 不引入新的运行时依赖。
- 不重构旧版 `MessageList` / `MessageBubble` / `InputArea`（保留兼容，本次只增强新版 `message/` + `conversation/` + `prompt-input/` 体系）。
- 不做多会话、i18n 等已独立成节的能力。

## 2. 原始需求

1. Playground 响应式消息列表：宽屏显示更宽的消息；消息列表支持设置消息靠左或靠右；支持用户消息在一侧显示。
2. 新建双列消息组件：左右双列同时呈现，用于收集用户偏好数据；两列最下方各有一个按钮，按钮文案「我更喜欢这个回复」。
3. 移动端输入组件：高度更低；底部不显示描述文字；按屏幕宽度隐藏/展示。
4. 可配置主题项（如响应式宽度）自动加入主题配置变量，并设计一个 hook 方法。

## 3. 已确认的关键决策

| 决策点 | 结论 |
|---|---|
| 消息对齐 | 提供 `layout` 属性，`'im'`（左右分列）与 `'stacked'`（统一对齐）两种模式都可切换 |
| 对齐配置位置 | 放在 `Conversation` 容器层，通过 `provide/inject` 下发给 `Message`，单点配置 |
| 双列组件本质 | A/B 偏好对比（左右各一候选回复），收集偏好数据 |
| 双列组件数据接入 | 独立组件 + props 驱动，不侵入 core 的 `Message` 类型 |
| 偏好按钮交互 | 左右两列各自底部各一个「我更喜欢这个回复」按钮，点哪列即偏好哪列 |
| 配置 hook 形态 | 新增 `useLayoutConfig`：结构化配置 → CSS 变量 + 注册 `tokens-meta` |
| 移动端适配策略 | 使用容器查询 `@container`（非视口 `@media`），符合组件库规范 |
| 组件归属 | `@ai-chat/vue` 公共库正式组件（带测试 + 文档），playground 同步演示 |

## 4. 功能需求

### FR-1 消息对齐（Conversation + Message）

- `Conversation` 新增 prop：
  - `layout?: 'stacked' | 'im'`，默认 `'stacked'`（向后兼容现状布局）。
  - `messageAlign?: 'left' | 'right'`，默认 `'left'`。
    - `stacked` 模式：所有消息整体靠 `messageAlign` 侧。
    - `im` 模式：用户消息靠 `messageAlign` 侧，AI 消息靠对侧。
- `Conversation` 通过 `provide('messageLayout', { layout, messageAlign })` 下发。
- `Message` 读取注入值，结合自身 `from`（user/assistant/system）计算修饰类：
  - `stacked`：`ai-chat-message--stacked` + `ai-chat-message--align-{left|right}`。
  - `im`：`ai-chat-message--im-user` / `ai-chat-message--im-assistant`，按 `messageAlign` 决定 user 落在哪一侧。
- 对齐纯 CSS 实现（`flex-direction` + 头像 `order` + `align-self` / `margin-inline`），无 JS 重排。
- `Message` 未检测到注入（旧用法）时回退到现状布局，零破坏。

### FR-2 响应式消息宽度

- 消息内容区容器以 `--ai-chat-content-max-width` 限宽；容器查询 `@container (min-width: 1100px)` 时切换为 `--ai-chat-content-max-width-wide`（更宽，满足「宽屏显示更宽的消息」）。1100px 阈值保证主区扣除侧边栏后仍有足够横向空间。
- IM 模式下单条气泡以 `--ai-chat-message-max-width` 限宽，避免宽屏气泡过宽。
- 消息区容器设 `container-type: inline-size`，所有断点一律容器查询。

### FR-3 ComparisonMessage 组件

- Props：
  ```ts
  interface ComparisonMessageProps {
    left: string                 // 候选 A 内容（markdown）
    right: string                // 候选 B 内容（markdown）
    leftLabel?: string           // 默认 '回复 A'
    rightLabel?: string          // 默认 '回复 B'
    chosen?: 'A' | 'B' | null    // 受控选中（可选）
    buttonLabel?: string         // 默认 '我更喜欢这个回复'
    stackOnMobile?: boolean      // 默认 true，窄屏堆叠为上下
    disabled?: boolean           // 禁用选择
  }
  ```
- Emits：
  ```ts
  { prefer: [{ chosen: 'A' | 'B'; left: string; right: string }] }
  ```
- Slots：
  - `#left` / `#right`（props: `{ label: string }`）：自定义列内容，覆盖 `left`/`right` props。
  - `#action-left` / `#action-right`：自定义底部按钮。
- 行为：
  - 布局为 CSS Grid 两列（`grid-template-columns: 1fr 1fr`），每列 = 标题（label）+ `MessageContent`(markdown) + 底部按钮。
  - 点击某列按钮 → 内部状态置为该列（非受控）并 emit `prefer`；`chosen` 受控时由父决定高亮。
  - 已选中列加高亮修饰类（边框/背景用主题变量）。
  - 窄屏（容器查询 < `--ai-chat-mobile-breakpoint`）Grid 自动堆叠为单列上下排列。
  - 复用 `@ai-chat/vue` 现有 `MessageContent` 渲染 markdown（已支持 Shiki / KaTeX / 流式）。

### FR-4 useLayoutConfig hook

- 签名：
  ```ts
  interface LayoutConfig {
    contentMaxWidth?: number       // → --ai-chat-content-max-width
    contentMaxWidthWide?: number   // → --ai-chat-content-max-width-wide
    messageMaxWidth?: number       // → --ai-chat-message-max-width
    inputMaxHeight?: number        // → --ai-chat-input-max-height
    inputMaxHeightMobile?: number  // → --ai-chat-input-max-height-mobile
    mobileBreakpoint?: number      // → --ai-chat-mobile-breakpoint
    layout?: 'stacked' | 'im'      // 结构配置（透传给 Conversation prop）
    messageAlign?: 'left' | 'right'
  }
  function useLayoutConfig(
    containerRef: Ref<HTMLElement | undefined>,
    config: MaybeRefOrGetter<LayoutConfig>,
  ): {
    vars: ComputedRef<Record<string, string>>  // 尺寸类 → CSS 变量字典（喂给 Conversation.customTheme）
    layoutProps: ComputedRef<{ layout?: 'stacked' | 'im'; messageAlign?: 'left' | 'right' }>
    state: ComputedRef<LayoutConfig>
  }
  ```
- 机制：
  - 尺寸/断点字段映射为 `{ '--ai-chat-xxx': '${value}px' }`，**hook 本身不直接操作 DOM**，仅产出 `vars` 字典；由宿主传入 `Conversation.customTheme`，复用 `Conversation` 内已有的 `useThemePreset` 单点写入容器（全组件只有一个 inline-style 写入点）。
  - `layout` / `messageAlign` 不变量化，作为 `layoutProps` 返回，供宿主透传给 `Conversation` 的 `layout` / `messageAlign` prop。
  - `state` 响应式返回当前生效配置。
- 新增的 CSS 变量同步登记进 `tokens-meta`（group「原始·尺寸」/ 新增「原始·断点」，type `size`，带 `min`/`max`/`unit`），ThemeBuilder 即可可视化调整。

### FR-5 PromptInput 移动端优化

- `PromptInput` 容器设 `container-type: inline-size`，用 `@container` 查询：
  - 窄屏（容器宽度 < `--ai-chat-mobile-breakpoint`）：
    - textarea `max-height` 取 `--ai-chat-input-max-height-mobile`（低于桌面端 `--ai-chat-input-max-height`）。
    - 减小 `padding`。
    - `__disclaimer`（「AI Chat UI 可能会产生不准确…」）与输入区 hint（「Enter 发送，Shift+Enter 换行」）`display: none`。
  - 宽屏恢复桌面端表现。
- 行为对宿主透明，无新增必填 prop；可通过 `useLayoutConfig` 的 `inputMaxHeightMobile` / `mobileBreakpoint` 调节。

## 5. 主题 Token 扩展

`packages/vue/src/styles/tokens.css` 原始层新增：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `--ai-chat-content-max-width-wide` | `1024px` | 宽屏消息区限宽 |
| `--ai-chat-message-max-width` | `480px` | IM 模式单条气泡限宽 |
| `--ai-chat-input-max-height-mobile` | `120px` | 移动端输入框最大高 |
| `--ai-chat-mobile-breakpoint` | `640px` | 容器查询移动端断点 |

`tokens-meta.ts` 为上述每项新增 `TokenMeta`（`layer: 'primitive'`，`type: 'size'`，`unit: 'px'`，合理 `min`/`max`）。`--ai-chat-mobile-breakpoint` 归入新 group「原始·断点」。

> 已存在的 `--ai-chat-content-max-width`(768px)、`--ai-chat-input-max-height`(200px) 不改默认值，仅确保已在 `tokens-meta` 登记（已登记）。

## 6. 非功能需求

- **向后兼容**：所有新增 prop 可选，默认值复刻现状；不传则行为不变。
- **零新依赖**：纯 Vue + CSS，markdown 渲染复用现有 `MessageContent`。
- **样式隔离**：新增类名统一 `ai-chat-` 前缀，颜色/尺寸均用 `--ai-chat-*` 变量，不硬编码色值。
- **容器查询优先**：响应式断点一律 `@container`，不用 `@media`（组件库原则）。
- **SSR 安全**：`useLayoutConfig` 写 inline style 仅在 `onMounted` 后执行，避免 SSR 不匹配。
- **类型完备**：所有 props/events/slots 有 TS 类型并从包入口导出。

## 7. 架构与数据流

```
宿主
 ├─ useLayoutConfig(config) ──► vars (CSS变量字典) ──► Conversation.customTheme
 │                          └─► layoutProps ─────────► Conversation.layout / messageAlign
 │
 └─ <Conversation :layout :message-align :custom-theme="vars">
       ├─ provide('messageLayout', { layout, messageAlign })
       ├─ <Message v-for> ──► inject('messageLayout') ──► 修饰类 ──► CSS 对齐
       ├─ <ComparisonMessage :left :right @prefer> ──► MessageContent 渲染 ──► emit prefer
       └─ <PromptInput> ──► @container 窄屏紧凑 + 隐藏 disclaimer/hint
```

组件依赖方向不变（`vue` → `core`），`ComparisonMessage` 与 `useLayoutConfig` 位于 `packages/vue/src`，从 `@ai-chat/vue` 入口导出。

## 8. 测试计划（Vitest + @vue/test-utils）

- `Conversation` / `Message` 对齐：
  - `layout='im'` 时 user 修饰类与 assistant 修饰类正确；`messageAlign='right'` 反转两侧。
  - `layout='stacked'` 时统一 `--align-*` 类。
  - 无注入时回退现状（不报错）。
- `ComparisonMessage`：
  - 默认渲染两列 + 两个按钮，文案正确。
  - 点击左/右按钮分别 emit `prefer`，`chosen` 为对应列。
  - `chosen` 受控时高亮与父值一致。
  - `#left`/`#right` slot 覆盖 props 内容。
- `useLayoutConfig`：
  - 各尺寸字段正确映射为带 `px` 的 CSS 变量字典。
  - `layout`/`messageAlign` 进入 `layoutProps`、不进入 `vars`。
  - `state` 随 config 响应式更新。
- `PromptInput`：窄屏容器下 disclaimer 节点存在但 `display:none`（jsdom + ResizeObserver polyfill 已有）。
- 覆盖率维持各包门禁（core 不受影响；vue ≥70%）。

## 11. 风险与取舍

- **容器查询兼容性**：2026 年浏览器覆盖率 >95%，项目第 11 章已确认采用；必要时 `@supports` 兜底。
- **IM 模式与现有 `MessageActions` 布局**：用户消息靠右后，actions 悬浮位置需复核，避免溢出。
- **inline-style 单点写入**：`useLayoutConfig` 不写 DOM，其 `vars` 与预设 vars 都经 `Conversation.customTheme` 走 `useThemePreset` 单点写入；`useThemePreset` 现有逻辑为「先清相关 key 再写，customTheme 后写覆盖 preset」，key 重叠时 customTheme（含 layout vars）优先。
