# 服务端网关与 agents 包需求规格

> 日期：2026-08-21 ｜ 状态：已确认（用户选定方案 A，直接进入实施）
> 关联：课程第 15 章三包架构（agents/tools/server）；`07-Vercel发布分支与部署-20260821.md`

## 1. 背景与决策

组件库前端已通过 `ChatAdapter` 与后端解耦，文档站由 `@toimc/mock-server`（私有 Hono 服务）支撑。本期把服务端能力沉淀为可发布的通用网关：

- **转发目标**：真实 LLM + mock 双后端。API Key 只存在于服务端 `ModelConfig`
- **Provider 范围**：v1 实现 OpenAI 兼容协议（覆盖 OpenAI/DeepSeek/GLM/Kimi/OpenRouter 等）+ Anthropic 原生协议；Google 等留扩展点
- **架构**：按课程第 15 章——`@toimc/agents`（模型调用纯逻辑，零外部依赖）+ `@toimc/server`（Hono HTTP 层）两个**公开发布**包
- **占位**：Orchestrator（ReAct 循环）与 tools 包不进本期；`ToolDefinition` 类型暂入 agents 导出；`ChatRequest.tools` 预留可选字段
- **mock 归属**：剧本引擎与会话内存存储留在私有 `@toimc/mock-server`，不发 npm；mock-server 改造为基于 `@toimc/server` 组装的演示服务
- **组装形态**：方案 A——`createChatGateway()` 工厂 + 底层路由/中间件双导出

## 2. 包结构

```

    src/

      routes/chat.ts          # POST /chat：SSE StreamChunk + 收集 + onComplete
      routes/models.ts        # GET /models：注册表公开视图（绝不含 apiKey）
      routes/health.ts        # GET /health
      middleware/auth.ts      # Bearer token（默认关）
      middleware/rate-limit.ts# 内存滑动窗口（默认关）
  mock-server/                # 改造，保持私有
```

依赖方向：`server → agents → core(仅类型)`；`mock-server → server + agents`。agents 零外部依赖（原生 fetch），server 依赖 hono。

## 3. 核心接口

```ts
// agents
interface ModelConfig {
  id: string                  // 对外模型 id（前端 model 参数）
  provider: string            // 'openai-compat' | 'anthropic'
  model: string               // 上游真实模型名
  apiKey: string
  baseURL?: string
  name?: string               // /api/models 展示名
  description?: string
}
interface ChatRequest {
  messages: { role: 'system'|'user'|'assistant'; content: string }[]
  signal?: AbortSignal
  temperature?: number
  maxTokens?: number
  tools?: ToolDefinition[]    // 占位，本期不消费
  passthrough?: Record<string, unknown>  // 网关不解释的请求体字段原样透传
}
interface IModelAdapter {
  chat(req: ChatRequest): Promise<ChatResponse>
  chatStream(req: ChatRequest): AsyncGenerator<StreamChunk>  // 复用 @toimc/core 的 StreamChunk
}
class ModelRegistry {
  register(config: ModelConfig): this            // 按 provider 自动建适配器
  registerAdapter(id, adapter, info?): this      // 自定义适配器（mock 等）
  get(id): RegisteredModel                       // {config|info, adapter}
  list(): ModelPublicInfo[]                      // 无 apiKey
}

// server
function createChatGateway(options: GatewayOptions): Hono
interface GatewayOptions {
  models: ModelRegistry | ModelConfig[]
  basePath?: string                              // 默认 '/api'
  cors?: boolean | CORSOptions                   // 默认 true
  logging?: boolean                              // 默认 false（hono/logger）
  auth?: { tokens: string[] } | { verify(token): boolean|Promise<boolean> }
  rateLimit?: { windowMs?: number; max?: number; keyBy?(c): string }
  defaultModel?: string                          // 缺省取注册表第一个
  chat?: { onComplete?(result: ChatCompletionResult): void|Promise<void> }
}
```

## 4. 线协议（与现有 mock-server 完全兼容，前端 sse-adapter 零改动）

- `POST {basePath}/chat`：body `{ conversationId?, messages:[{role,content}], model?, speed?, … }`。网关提取 `messages`/`model`，其余字段（conversationId、speed 等）整体进 `ChatRequest.passthrough`
- 响应 `text/event-stream`：`event: chunk` + `data: <StreamChunk JSON>`，`done` 收尾；剧本执行异常以 `error` chunk 收尾保持可解析
- 错误码：body 非 JSON / messages 缺失 → 400；未知 model → 400（清晰消息）；auth 未过 → 401；限流 → 429
- `GET /models` → `{ models: [{id,name,description}] }`；`GET /health` → `{status:'ok'}`

## 5. 关键行为

- **流收尾钩子**：chat 路由在流式过程中按 chunk 类型累积出助手消息（text/thinking/tool_call→tool_result 配对），流结束触发 `onComplete({body, assistant, model, durationMs, aborted})` —— mock-server 用它写回会话存储（替代原 collectAssistant 内联逻辑）
- **中止**：`stream.aborted` 停止吐块；AbortSignal 透传到上游 fetch；中断不算错误
- **多运行时**：网关只导出 fetch 风格 Hono app；`@hono/node-server` 留在消费侧（mock-server/index.ts）。Vercel 部署沿用既定模式（esbuild 预打包 + 具名导出 + rewrites）
- **mock 模型差异化**：mock-pro 默认剧本；mock-flash 速度倍率 0.4；mock-thinking 始终前置思考剧本（与 /api/models 描述对齐）

## 6. 测试（红灯先行 + 双盲分工）

- 测试由独立 subagent 仅依据类型定义与线协议文档编写，禁止读实现源码
- 覆盖：Registry 注册/查找/公开视图脱敏；SSE 解析正常/半截帧/CRLF；两适配器 mock fetch 下的 chat 与 chatStream（含 reasoning/thinking 映射、错误状态码、中断）；网关 400/401/429/正常流/done 收尾/onComplete 调用/模型缺省回退
- mock-server 既有 app.test.ts 全部保持绿色（线协议回归保障）

## 7. 交付链路

1. feature 分支实现 + 全绿 → `--no-ff` 合并 `dev`
2. 发版：dev → master，changeset（agents/server 首发 minor），`scripts/publish.sh`（PACKAGES 增补两包）发布 npm
3. Vercel：deploy/vercel worktree 合并 master → build → CLI 部署（token 由用户提供）
4. 文档：docs 新增服务端指南页 + 导航；mock-api.md 线协议不变无需改行为描述
