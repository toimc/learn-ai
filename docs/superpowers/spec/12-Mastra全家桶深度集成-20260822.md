# Mastra 全家桶深度集成 — 需求规格

> 日期：2026-08-22 ｜ 状态：设计已获用户批准，作为多 subagent 并行开发的接口契约基准
> 前置：spec 10（`@toimc/agents/mastra` 子路径）、spec 11（运行时 Provider 注册，已合并 dev `3d5719b`）
> 调研依据：四方 subagent 报告（骨架 / 前端适配 / 全家桶能力 / 冲突审计），关键官方事实均已核对 mastra.ai 文档与 @mastra/core 1.60.0 dist 类型

## 1. 背景与目标

spec 10/11 把 Mastra 定位为「可插拔适配器之一」；本期升级为**服务端核心主力**：新建 `packages/mastra-app` 标准 Mastra 工程，走 `@mastra/hono` 官方集成方式，分期引入 workflows / observability / evals 全家桶能力。

### 用户已拍板的四个决策

1. **集成深度**：全家桶（Agent 运行时 + `@mastra/hono` API 面 + workflows/evals/observability 分期）
2. **前端协议**：新增消费 Mastra 原生端点的 **Mastra ChatAdapter**（前端转协议），useChat/组件零改动，`StreamChunk` 仍是 core 资产
3. **旧端点**：共存——自有 `/api/chat`（8787）+ 3 mock 保留为组件库参考实现与离线开发基础，Mastra 端点（4111）为主力
4. **部署**：先本地跑通，部署验证后议（P5 专项）

### 双链路定位（叙事基准）

- **8787 链路**（spec 10/11，服务端转协议）：组件库官方接入方式，宿主零 Mastra 依赖，「快速接入 Provider」
- **4111 链路**（本期，前端转协议）：Mastra 全家桶主力工程（原生端点 + Studio + workflows + observability）

## 3. Phase 1 — `packages/mastra-app` 骨架

### 3.1 目录与文件职责

```
packages/mastra-app/
├── package.json        # @toimc/mastra-app，private、type:module；mastra CLI 装本包 devDeps
├── tsconfig.json       # extends ../../tsconfig.base.json，noEmit、types:["node"]（对齐 mock-server）
├── .env.example        # MASTRA_APP_MODEL / MASTRA_APP_MODEL_URL / MASTRA_APP_TOKEN / MASTRA_APP_PORT / MASTRA_APP_TELEMETRY
└── src/
    ├── index.ts        # Hono 入口（serve 4111）
    └── mastra/         # mastra CLI 认的标准结构（--dir src/mastra）
        ├── index.ts    # export const mastra = new Mastra({...}) —— 必须静态命名导出（模块级 let CLI 拿不到）
        ├── agents/chat-agent.ts
        ├── tools/get-time.ts
        ├── tools/get-weather.ts
        ├── workflows/  # P3 预留（.gitkeep）
        └── memory.ts
```

- **无需 vite 构建**：私有应用包，`tsx watch` 直跑；不用 `mastra init` 交互生成，手工按其结构落文件即可被 CLI 识别
- **依赖**（deps）：`@mastra/core@^1.60.0`（锁版）、`@mastra/hono`、`@mastra/memory@^1.27`、`@mastra/libsql@^1.21`、`hono@^4.10`、`@hono/node-server@^1.19`、`zod@^4.4`；devDeps：`mastra`（CLI）、`tsx`、`typescript`、`vitest`、`@types/node`
- **scripts**：`dev: "tsx watch --env-file-if-exists=.env src/index.ts"`、`studio: "mastra studio"`（默认连 4111 + prefix /api 零 flag）、`build: "mastra build"`、`start: "mastra start"`、`test`/`type-check` 对齐 mock-server
- **禁止引入任何 `@toimc/*` workspace 包**：纯 npm 依赖，保持标准工程自包含（避开未编译 TS 的坑）

### 3.2 Hono 入口（src/index.ts）

```ts
const app = new Hono<{ Bindings: HonoBindings; Variables: HonoVariables }>()
app.get('/health', c => c.json({ status: 'ok' }))   // 先注册，不受后续中间件影响
app.use('/api/*', cors())                            // 4111×5173 跨源（参照 @toimc/server create-gateway 模式）
if (process.env.MASTRA_APP_TOKEN)
  app.use('/api/*', bearerAuth({ tokens: [process.env.MASTRA_APP_TOKEN] }))  // 复刻 mock-server bearerAuth 语义（401 {error:'Unauthorized'}）
const server = new MastraServer({ app, mastra })     // 不设 prefix：保持默认 /api，studio 零 flag 直连
await server.init()
serve({ fetch: app.fetch, port: Number(process.env.MASTRA_APP_PORT ?? 4111) })
```

- 缺 `MASTRA_APP_MODEL` 启动时报可读错误（指明缺哪个 env）
- 构建期选项必须是 `new Mastra({})` 直属性，不能工厂/展开传入（mastra build 提取不到）

### 3.3 Agent / 工具 / Memory

- `chat-agent`：`new Agent({ name: 'chat-agent', model, instructions, tools, memory })`；model 由 env 组装（`MASTRA_APP_MODEL_URL` 存在走 `{id, url}` 对象，否则路由串如 `deepseek/deepseek-chat`）
- 工具：`get_time` / `get_weather` **复制**自 `packages/mock-server/src/mastra/tools.ts`（~100 行两份，头注释互指来源；mock-server 原文件不动，spec 11 的 `registerRuntimeProvider` 仍在原处 import）；涨到 3+ 个再议上提
- Memory：`LibSQLStore({ url: 'file:.temp/mastra-app.db' })` + `ensureDbDir()`（libsql 不建父目录的已知坑，实现参照 mock-server）；**db 文件名必须与 mock-server 的 `.temp/mastra.db` 区分**（两服务 CWD 不同天然是两个文件，显式异名根除 SQLITE_BUSY 与 thread 混库）

### 3.4 资源隔离表

| 资源 | mock-server | mastra-app |
|---|---|---|
| 端口 | 8787 | 4111（Mastra 生态默认；与 `mastra dev` 同口，**二者互为替代不同时跑**，文档注明） |
| Memory db | `file:.temp/mastra.db` | `file:.temp/mastra-app.db` |
| env 前缀 | `MASTRA_MODEL`/`MASTRA_TELEMETRY` | `MASTRA_APP_*`（规避与 CLI 自有 `MASTRA_TELEMETRY_DISABLED` 撞名） |

- `.env` 放 `packages/mastra-app/` 目录（根 .gitignore 的 .env 规则已覆盖）；模型 key 按 Mastra 路由约定命名（如 `DEEPSEEK_API_KEY`），两包各管各的
- 根 `.gitignore` 追加 `.mastra/`（无斜杠前缀匹配任意层级）
- 根 vitest 自动收集 `packages/*/src/**/*.test.ts`，新测试免配置入 `pnpm test`；注意 vitest 包级作用域坑（根目录跑，或 `MOCK_SERVER_PORT` 改端口，见记忆）

## 4. Phase 2 — 前端 Mastra ChatAdapter + 后端选择器

### 4.1 mastra-adapter（`packages/playground/src/adapters/mastra-adapter.ts`，私有）

- **位置决策**：playground 私有而非新建公共包 `@toimc/adapter-mastra`——塞特定后端进公共包反而弱化「后端无关」叙事，且 1.60 线格式未经 HTTP 实测前不宜固化成公共 API；升级路径 = 文件级搬迁（sse-adapter 已有私有先例）
- **请求**：`fetch POST {base}/api/agents/chat-agent/stream`，body `{ messages: [{role, content}], memory: { thread: conv.id, resource: 'ai-chat-playground' }, modelSettings? }`；`opts.signal` 直通
- **SSE 解析**：复用 `packages/playground/src/mock/sse-adapter.ts` 已导出的 `parseSseStream`（import 不复制）
- **映射器**：与 `packages/agents/src/mastra/index.ts` 服务端映射同构（`pendingArgs`/`completedArgs`/`toolNames` 三 Map），事件映射表：

| Mastra 原生事件 | StreamChunk | 备注 |
|---|---|---|
| `text-delta` | `{type:'text'}` | payload.text |
| `reasoning-delta` | `{type:'thinking'}` | |
| `tool-call-input-streaming-start` | `tool_call`（id+name 壳帧） | useChat 建 calling 态 entry |
| `tool-call-delta` | 不发帧 | 按 toolCallId 累积 argsTextDelta |
| `tool-call-input-streaming-end` | `tool_call`（完整 arguments） | toolName 从 start 帧回填 |
| `tool-call`（完整调用） | `tool_call` 完整帧 | 按 completedArgs 去重防双发 |
| `tool-result` / `tool-error` | `tool_result` | isError → toolError |
| `error` | `error` 后终止 | |
| `finish` | `done` 后终止 | |
| `start`/`step-*`/`raw`/`source` 等 | 丢弃 | 对齐服务端注释 |

- **done 帧自补**：流自然结束兜底补 `{type:'done'}`（原生端点不保证发；这是与网关链路的关键差异）
- **错误/中断**：HTTP 非 2xx → `throw Error`（useChat 转 state.error）；AbortError/signal.aborted → 静默 return（对齐 sse-adapter）
- **memory 双份历史**：agent 配 memory 时前端是否只发增量——以 P1 DoD 的 curl 实测样例定（默认方案：发全量 + thread；实测重复则切增量）

### 4.2 dispatch-adapter 融合（改造 `packages/playground/src/mock/dispatch-adapter.ts`）

`DispatchConversation` 增可选 `backend?: 'mock-server' | 'mastra'`，会话创建时快照（切换只影响新会话，对齐 spec 11 语义）：

```
sendMessage(opts):
  conv = getConversation()
  if conv?.backend === 'mastra':  yield* mastraAdapter.sendMessage(opts)   # conv.id → thread
  elif conv?.model:               yield* sseAdapter.sendMessage(opts)      # 8787，spec 11 现状
  else:                           yield* mockAdapter.sendMessage(opts)     # 本地剧本
```

## 5. Phase 3 — Workflows（概要，届时细化 plan）

进：1-2 个示范 workflow 覆盖 `then/parallel/branch/foreach`；step 内跑 agent（`writer` 流式透传）；前端 Vue 节点状态图消费官方事件流（`POST /api/workflows/:id/stream`，5 类事件：workflow-start/step-start/step-output/step-progress/step-result/workflow-finish → 节点状态机）；一个 suspend/resume 人工确认断点（LibSQL 快照）。
不进：Dynamic workflows（beta）、Scheduled/Workers、Time travel。注意：workflow `.stream()` 事件**不是** AI SDK UIMessage 流，前端不得直连 useChat。

## 6. Phase 4 — Observability + Evals（概要）

- `@mastra/observability`（1.17+，独立包——**@mastra/core 1.60 的 observability 子路径不含文档中的类**）+ composite storage（LibSQL + **DuckDB** observability 域，Studio Metrics 硬性要求 OLAP）→ Studio Metrics/Traces/Logs 全开
- mock-server 旧 `telemetry` 接线（`attachMastraInstance`）同期迁移（API 已 deprecated）
- 前端评分 → `observability.addFeedback`（消息 metadata.traceId 天然锚定）；1 个 LLM-judge scorer + 1 个预置 scorer live 挂 agent；CI `runEvals()` + Vitest 阈值断言
- 不进：第三方 exporter（留 exporters 数组扩展位）、生产 ClickHouse、datasets UI

## 7. 非功能需求与整合约束

- **依赖纪律**：`@mastra/core` 全仓锁 `^1.60.0`（对齐 agents peer；脚手架默认新版会双份安装且偏离 1.60 实测基线）；`@toimc/agents` 主入口依赖树零新增（不变）；mastra-app 不 import 任何 `@toimc/*`
- **零回归**：8787 链路（3 mock + spec 11 Provider）行为完全不变；`guide/server.md` 增补端口互斥一句（mock-server 的 `npx mastra dev` Studio 与 mastra-app 同占 4111）
- **安全**：MASTRA_APP_TOKEN 可选 Bearer；模型 key 只在 mastra-app `.env`（不提交）；`GET` 类端点不回显 key
- **测试纪律**：红灯先行 + 双盲分工（测试 subagent 只读本 spec 与类型定义，禁止读实现源码）；预期值三来源（手写字面量/文档写明值/独立第三方实现）
- **文档同步**（docs-sync 门禁）：`packages/docs/guide/mastra.md` 全量更新（双链路定位 + mastra-app 快速开始 + 选型对比 + 交叉引用 server.md）；README 包依赖图更新
