# 01-Markdown 渲染组件需求文档

> 文档类型：需求规格（Spec）
> 日期：2026-06-18
> 关联调研：`docs/01-Vue生态大模型实时流Markdown渲染方案调研.md`
> 涉及包：`@ai-chat/markdown`（主体）、`@ai-chat/vue`（接入）

---

## 1. 背景与目标

ai-chat-ui 是后端无关的 Vue 3 大模型会话组件库。`@ai-chat/markdown` 包当前是**手写正则的 MVP**（`simpleMarkdown` 仅支持粗体/标题/纯文本代码块），无法满足大模型会话的真实需求。

本需求将该组件升级为**面向大模型实时流会话**的成熟 Markdown 渲染方案：代码高亮、数学公式、图表、高性能、逐 token 流式渲染、与 `@ai-chat/vue` 消息流无缝集成。

**核心挑战**：逐 token 到达时的增量渲染——避免全量重解析导致的闪烁、卡顿、滚动位置丢失、代码块着色断裂。

---

## 2. 现状

| 文件 | 现状 |
|------|------|
| `packages/markdown/src/MarkdownRenderer.vue` | 正则 `simpleMarkdown`，仅粗体/标题/行内代码/纯文本代码块 |
| `packages/markdown/src/CodeBlock.vue` | 纯文本、无高亮骨架 |
| `packages/markdown/src/LatexBlock.vue` | CSS 字体伪装、无真实 LaTeX |
| `packages/vue/src/message/MessageContent.vue` | **纯 slot 容器**，不使用 markdown 包 |
| `packages/vue/src/shared/StreamText.vue` | 纯文本 + 闪烁光标，不解析 markdown |
| `packages/vue/src/composables/useScrollAnchor.ts` | 已存在，可复用 |

**关键结论**：markdown 包存在但基本未被 vue 包使用——内容经 slot 纯文本传入。本需求要**让 markdown 渲染真正接入消息流**。

---

## 3. 需求范围

### 包含（完整版，5 个能力域）

1. **解析内核**：markdown-it + GFM + DOMPurify 消毒
2. **代码高亮**：基于 `@shikijs/stream` 的流式增量着色（VSCode 同款 TextMate 语法）
3. **数学公式**：KaTeX 同步渲染（`$...$` 行内 + `$$...$$` 块级）
4. **图表**：Mermaid 异步渲染 + 沙箱 iframe
5. **流式优化 + 自动接入**：容错截断、rAF 节流、provide/inject 可选依赖自动渲染

### 不包含（YAGNI）

- Markdown **编辑器**（本组件只做渲染，不做所见即所得编辑）
- 服务端渲染（SSR）专项优化（后续按需）
- 自定义语法扩展 DSL（仅支持标准 GFM + 公式 + Mermaid）
- 移动端手势增强

---

## 4. 功能性需求

### FR-1 Markdown 解析

- **FR-1.1** 采用 `markdown-it` 作为解析引擎（CommonMark 规范、插件生态、同步纯函数利于流式）
- **FR-1.2** 启用 `markdown-it-gfm`（表格、删除线、任务列表、URL autolink）
- **FR-1.3** `v-html` 前必须经 `DOMPurify.sanitize`（LLM 输出不可信）
- **FR-1.4** 配置 `breaks: false`，围 fence 单独处理换行（避免重蹈「换行穿透 `<pre>`」坑，见 commit `47e2db7`）
- **FR-1.5** 单例 `markdown-it` 实例（`useMarkdownIt` 缓存），避免每次渲染重建

### FR-2 代码高亮（流式）

- **FR-2.1** 采用 `@shikijs/stream` 的 `ShikiStreamTokenizer` 实现单代码块增量着色
- **FR-2.2** 利用 tokenizer 的 **grammar state** 保证多行代码着色连续（不逐行独立高亮导致颜色断裂）
- **FR-2.3** 按 **stable / unstable token** 区分渲染：stable token（已确定不变的行）缓存 DOM，unstable token（当前最后一行）每帧重渲
- **FR-2.4** `streaming=true` 时持续 `enqueue(chunk)`；`streaming=false` 时调用 `close()` 收尾
- **FR-2.5** 支持语言：js、ts、vue、jsx、tsx、json、bash、sh、html、css、scss、python、go、rust、md、yaml、sql（按需 bundle grammar，不全量）
- **FR-2.6** 未知语言回退纯文本，不报错
- **FR-2.7** Shiki **Dual Themes**（明暗双主题同时输出），配合 `useTheme` 暗色模式 CSS 切换不重渲

### FR-3 数学公式

- **FR-3.1** 采用 KaTeX 同步渲染（`katex.renderToString`）
- **FR-3.2** 支持 `$...$` 行内、`$$...$$` 块级两种语法（经 `markdown-it-texmath` 或等价插件，先块级 `$$` 后行内 `$` 的处理顺序）
- **FR-3.3** `throwOnError: false`：公式语法错误时显示原始文本，不中断渲染
- **FR-3.4** KaTeX CSS 按需引入

### FR-4 图表（Mermaid）

- **FR-4.1** 识别 ` ```mermaid ` 代码块，渲染为 Mermaid 图表
- **FR-4.2** Mermaid **动态 `import()`** 加载，不进主 bundle
- **FR-4.3** `streaming=true` 或 mermaid 块**未闭合时不渲染**，显示 loading 占位；闭合后 `nextTick` 触发 `mermaid.render`
- **FR-4.4** 渲染失败显示错误占位 + 原始文本
- **FR-4.5** **沙箱 iframe 渲染**（官方安全推荐），隔离图表中的潜在脚本注入

### FR-5 流式渲染优化

- **FR-5.1** `extractCompleteMarkdown(buffer)`：扫描未闭合的 ` ``` ` / `$$` 围栏，截到最后一个安全边界（未闭合代码块尾部临时剔除）
- **FR-5.2** `requestAnimationFrame` 节流，合并同一帧内多个 chunk，避免逐 token 全量重解析
- **FR-5.3** 渲染结果用 `shallowRef` 持有（避免深度响应式开销）
- **FR-5.4** 复用现有 `useScrollAnchor` 实现底部跟随 + 用户上滚暂停

### FR-6 自动接入（可选依赖）

- **FR-6.1** `@ai-chat/vue` 对 `@ai-chat/markdown` 保持 **optionalDependencies**，不强依赖
- **FR-6.2** `MessageContent.vue` 通过 `inject(markdownRendererKey, null)` 获取渲染器：**有注入 → 自动用 `MarkdownRenderer` 渲染 slot 文本**；无注入 → 回退纯 slot（现状）
- **FR-6.3** 导出 `provideMarkdownRenderer(component)` helper 与 `markdownRendererKey`，用户在应用入口一次性注入后全链路自动
- **FR-6.4** playground（VitePress）自动配置注入，开箱演示

## 5. 非功能性需求

| 维度 | 要求 |
|------|------|
| **性能** | 单条消息流式渲染期间主线程不卡顿（长代码块 rAF 帧率 ≥ 30fps）；稳定 token 不重复着色 |
| **安全** | 所有 `v-html` 经 DOMPurify；Mermaid 沙箱 iframe；LLM 输出视为不可信 |
| **体积** | Shiki grammar / KaTeX CSS / Mermaid 全部按需或动态加载；`@ai-chat/markdown` 对 `@ai-chat/vue` 零硬依赖 |
| **主题** | 全部颜色经 `--ai-chat-*` CSS Variables；Shiki Dual Themes 配合 `useTheme` 明暗切换 |
| **类型** | 完整 TypeScript 类型声明；Props/Events/Slots 类型导出 |
| **可访问性** | 代码块保留 `<pre><code>` 语义；公式输出 KaTeX 的 MathML（屏幕阅读器友好） |

## 6. 架构设计：两层流式架构

```
LLM chunk
  → useChat 拼接 message.content
  → MessageContent [inject renderer] → <MarkdownRenderer :content :streaming>
       【外层】useStreamingMarkdown
         ├─ extractCompleteMarkdown(content)      // 容错截断
         └─ rAF 节流合并 chunk
       → markdown-it.parse → 自定义 renderer
            ├─ code fence    → <CodeBlock :code :language :streaming>   // 【内层】ShikiStreamTokenizer
            ├─ $$/$ math     → KaTeX 同步渲染
            └─ ```mermaid    → <MermaidBlock :code>                      // 异步 + 沙箱
       → DOMPurify.sanitize → v-html
```

**两层分工**：

- **外层**（markdown-it）：处理整篇流式 markdown，负责容错截断与节流，识别块级结构
- **内层**（组件级）：`CodeBlock` 用 `ShikiStreamTokenizer` 做单代码块增量着色，stable/unstable token 分治；`MermaidBlock` 异步渲染

> `@shikijs/stream` 工作在**单代码块**层面（接受一个代码块的内容流），因此整篇流式必须由外层 markdown-it 先切分出代码块，再交给内层 tokenizer。这是本架构的关键设计决策。

## 7. 组件接口规格

### MarkdownRenderer.vue

| Prop | 类型 | 默认 | 说明 |
|------|------|------|------|
| `content` | `string` | `''` | 待渲染的 markdown 文本（可为流式 buffer） |
| `streaming` | `boolean` | `false` | 是否处于流式接收中（影响代码块 tokenizer 行为） |

- 渲染容器 `<div class="ai-chat-markdown">`，复用 `--ai-chat-*` 主题变量

### CodeBlock.vue

| Prop | 类型 | 说明 |
|------|------|------|
| `code` | `string` | 代码内容（流式中可能逐 chunk 增长） |
| `language` | `string` | 语言标识（未知则纯文本） |
| `streaming` | `boolean` | 流式中持续 `enqueue`，结束时 `close()` |

- 内部维护 `ShikiStreamTokenizer` 实例，stable token 缓存、unstable token 重渲
- header 显示语言名 + 复制按钮（复用现有 MessageActions 模式，可选）

### LatexBlock.vue

| Prop | 类型 | 说明 |
|------|------|------|
| `formula` | `string` | LaTeX 公式 |
| `display` | `boolean` | true=块级 `$$`，false=行内 `$` |

- `katex.renderToString(formula, { throwOnError: false, displayMode: display })`

### MermaidBlock.vue（新增）

| Prop | 类型 | 说明 |
|------|------|------|
| `code` | `string` | mermaid 图表源码 |

- 动态 `import('mermaid')` → `mermaid.render(id, code)` → 沙箱 iframe 注入 SVG
- loading / error 占位状态

### Composables 与工具

| 模块 | 职责 |
|------|------|
| `useMarkdownIt` | 单例 `markdown-it` 实例 + 插件配置（gfm / texmath / 自定义 fence） |
| `useStreamingMarkdown` | 容错截断 + rAF 节流，返回 sanitized HTML（shallowRef） |
| `useShikiTokenizer` | 单代码块 `ShikiStreamTokenizer` 生命周期（init/enqueue/close/dispose） |
| `extractCompleteMarkdown(buffer)` | 未闭合围栏截断（纯函数） |
| `provideMarkdownRenderer` / `markdownRendererKey` | vue 包可选注入 |

## 8. 数据流

1. LLM 产出 chunk → `useChat` 的 `for await` 消费流，拼接到 `message.content`
2. `MessageContent` 经 inject 拿到 renderer → 渲染 `<MarkdownRenderer :content="message.content" :streaming="isStreaming">`
3. `useStreamingMarkdown`：`extractCompleteMarkdown` → rAF 节流 → `md.render`
4. markdown-it 自定义 renderer 把 code fence/math/mermaid 映射到子组件
5. `CodeBlock` 的 `useShikiTokenizer` 增量着色；`MermaidBlock` 异步渲染
6. 整体 DOMPurify 消毒后 `v-html`
7. `useScrollAnchor` 维持滚动锚定

---

## 9. 错误处理与安全

| 场景 | 处理 |
|------|------|
| 公式语法错误 | KaTeX `throwOnError: false`，显示原始文本 |
| Mermaid 渲染失败 | 错误占位 + 原文，不中断整条消息 |
| Shiki tokenizer 异常 | try/catch 回退纯文本代码块 |
| 未知代码语言 | 纯文本渲染，不报错 |
| XSS 注入 | 所有 `v-html` 前 DOMPurify.sanitize |
| Mermaid 脚本注入 | 沙箱 iframe 隔离渲染 |
| 流式未闭合块 | `extractCompleteMarkdown` 截断到安全边界 |

## 12. 验收标准

- [ ] 大模型流式输出 markdown 时，标题/列表/表格/代码/公式/图表均正确渲染
- [ ] 流式过程中代码块着色连续（无颜色断裂），无整篇闪烁
- [ ] 滚动锚定正常（底部跟随 + 用户上滚暂停）
- [ ] 未闭合的代码块/公式不报错、不破坏后续渲染
- [ ] 暗色模式下代码高亮、公式、图表正确切换
- [ ] 不安装 markdown 包时，消息回退纯文本 slot，功能不报错
- [ ] DOMPurify 拦截恶意 `<script>` / onerror 等注入
- [ ] Mermaid 在沙箱 iframe 渲染，脚本注入被隔离
- [ ] 测试覆盖率 ≥ 80%，全部通过
- [ ] `pnpm type-check` / `pnpm lint` 通过
- [ ] markdown 包体积：主入口不含 mermaid，shiki grammar 按需
