# 测试工具链集成与开发测试文档 需求规格

- 日期：2026-08-21
- 分支：`feat/testing-toolchain`（基于 `dev`）
- 状态：已获用户批准

## 1. 背景与目标

项目已有 Vitest 4 + `@vue/test-utils` + jsdom 的单元/组件测试体系（42 个测试文件，根级统一 `vitest.config.ts`），但缺少：

1. 主流的用户行为驱动测试工具（Testing Library），无法从"宿主使用组件库"的视角写测试
2. 跨组件组合的集成测试层（现有测试全部是单组件/单模块级）
3. 面向贡献者的开发与测试文档（指南侧栏只有一个"开发指南"分组）

目标：引入 Testing Library 三件套补齐集成测试层，提供一个最基础的可运行示例，并在文档指南中新增"开发与测试"分组。

## 2. 范围

### 做

- 引入 `@testing-library/vue` + `@testing-library/jest-dom` + `@testing-library/user-event`（根 devDependencies）
- 新建根级 `tests/setup.ts`：注册 jest-dom matchers + jsdom 缺失 API 的统一 polyfill（`matchMedia`、`ResizeObserver`）
- `vitest.config.ts` 增加 `setupFiles`，其余配置（include / coverage / globals / environment）不变
- 新增 `packages/vue/src/integration/chat-flow.test.ts`：宿主视角的完整聊天流程集成测试（基础测试示例）
- `packages/docs` 新增两篇指南：`guide/development.md`（开发指南）、`guide/testing.md`（测试指南）
- `.vitepress/config.ts` 的 `/guide/` sidebar 新增"开发与测试"分组，顶部导航"指南"下拉同步加入口

### 不做

- 不迁移现有 42 个 `@vue/test-utils` 测试文件（并存策略：VTU 查实现细节、TL 查用户行为，互补）
- 不引入 Playwright / E2E（用户已明确选择 Vitest + Testing Library 形态）
- 不改动现有覆盖率门禁配置（coverage.include 仍只有 markdown 包）

## 3. 设计决策

### 3.1 并存渐进（已选）

现有测试一律不动；新增测试（集成测试与基础示例）用 Testing Library 风格写。理由：零回归风险；符合社区主流；不违反"不重构未被要求重构的代码"规范。

### 3.2 基础测试示例

`packages/vue/src/integration/chat-flow.test.ts`：

- 组装"宿主视角"完整聊天页：`Conversation` + `Message` + `PromptInput` + `useChat` + 内联 mock ChatAdapter（`async *` 生成器 yield 文本 chunk 模拟流式）
- Testing Library 用户行为驱动：`userEvent.type()` 输入 → 点击发送 → `await screen.findByText()` 断言流式回复逐字上屏
- 用例：正常流式对话上屏、发送后输入框清空、（可选）空输入不发送
- 现有 include pattern `packages/*/src/**/*.{test,spec}.{ts,tsx}` 天然覆盖，无需改收集规则

### 3.3 setup 文件

`tests/setup.ts` 放根级（全局配置性质，不属于任何包）：

```ts
import '@testing-library/jest-dom/vitest'
// matchMedia / ResizeObserver polyfill（jsdom 缺失，只增不减，对现有测试无影响）
```

落实测试规范"polyfill 在 setup 文件统一处理"，替代散落在个别测试里的补丁。

### 3.4 文档

`/guide/` sidebar 新增分组：

```ts
{ text: '开发与测试', items: [
  { text: '开发指南', link: '/guide/development' },
  { text: '测试指南', link: '/guide/testing' },
] }
```

- **开发指南**（`development.md`）：Monorepo 包结构与依赖方向、常用命令、编码规范要点（TS/Vue/测试三份 rules 摘引）、Git 分支模型概述
- **测试指南**（`testing.md`）：测试分层（单元=core 纯逻辑 / 组件=VTU / 集成=TL）、三件套用法（`render`/`screen`/`userEvent`，引用真实集成测试）、jest-dom matchers、如何跑单个测试、覆盖率门禁说明

## 4. 验收标准

1. `pnpm test` 全绿（含新集成测试），`pnpm type-check`、`pnpm lint` 三绿
2. docs 构建无新增警告，sidebar"开发与测试"分组两篇文档可访问
3. 现有 42 个测试文件零改动（`git diff` 验证）
4. 满足代码-文档同步门禁（测试基建变化已在 testing.md 说明）
