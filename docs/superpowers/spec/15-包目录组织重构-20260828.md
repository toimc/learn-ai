# 包目录组织重构：测试分离与模块化归置

- 日期：2026-08-28
- 状态：已批准（用户口头批准设计，本文件为落盘版）
- 分支：`feat/test-directory-restructure`（基于 `dev`，worktree 隔离）

## 1. 背景与问题

spec11（Mastra 深度集成与 dev-server 重组）完成后，仓库为 8 个活跃包：`agents` / `core` / `dev-server` / `docs` / `markdown` / `playground` / `server` / `vue`。当前存在两个目录组织问题：

1. **测试与源码混放**：89 个 `.test.ts` 全部与被测源码同目录（`foo.ts` ↔ `foo.test.ts`），src 树里测试文件与源码文件数量几乎 1:1，浏览与检索成本高。
2. **根级散件**：`vue` 包 4 个 deprecated 组件（ChatWindow / MessageList / MessageBubble / InputArea）与 `markdown` 包 4 个主组件（MarkdownRenderer / CodeBlock / LatexBlock / MermaidBlock）散在 `src/` 根，与「按功能模块组织」的既有结构（conversation/、message/、prompt-input/ 等）不一致。

现有规则 `.claude/rules/frontend-testing.md` 写着「测试文件放在被测模块旁，不集中建 `__tests__` 目录」——本设计**推翻该条款**，规则文件同步修改。

## 2. 目标结构（所有包统一）

```
packages/<pkg>/
├── src/               # 纯源码，零测试文件
│   ├── index.ts       # 包入口（src 根只留入口 / env.d.ts / 包级 types.ts）
│   └── <module>/      # 功能模块目录
├── __tests__/         # 与 src 平级，内部镜像 src 结构
│   └── <module>/
│       └── foo.test.ts
├── vite.config.ts
└── package.json
```

### 镜像规则

- `src/composables/useTheme.test.ts` → `__tests__/composables/useTheme.test.ts`
- 源码根级的测试（如 `src/sse.test.ts`）→ `__tests__/sse.test.ts`（保持根级）
- import 相对路径随镜像层级重写：`./useTheme` → `../../src/composables/useTheme`；`@toimc/*` 别名导入不受影响
- 全部用 `git mv` 保留重命名历史

## 3. 迁移范围

| 包 | 测试文件数 | 源码是否归置 |
|---|---|---|
| core | 4 | 否（已达标：adapter/ composables/ types/ utils/） |
| vue | 50 | **是**：4 个 deprecated 组件 → `src/deprecated/`，index.ts 导出路径同步 |
| markdown | 10 | **是**：4 个主组件 → `src/components/` |
| agents | 5 | 否（adapters/ mastra/ 已模块化，根级散件 ≤2 不成组） |
| server | 3 | 否（middleware/ routes/ mastra/ 已模块化） |
| dev-server | 11 | 否（spec11 刚完成重组） |
| playground | 6 | 否（adapters/ components/ composables/ mock/ 已达标） |
| docs | 0 | — |

**模块划分原则**（写入规则文件）：src 根只留 `index.ts` / `env.d.ts` / 包级 `types.ts`；同类职责文件 ≥2 个才成组归目录，禁止一文一目录。

## 4. 配套配置调整

| 文件 | 改动 |
|---|---|
| `vitest.config.ts` | `include` → `['packages/*/__tests__/**/*.{test,spec}.{ts,tsx}']`；coverage 的 `*.test.ts` 排除规则失效删除（保留 `types/**` 排除） |
| 各包 `tsconfig.json` | `include` 增加 `__tests__`（否则 vue-tsc / tsc type-check 漏掉测试文件）；构建包去掉 `rootDir: "src"`（构建全走 vite lib mode，rootDir 无实际作用且会触发 TS6059） |
| `eslint.config.js` | 无需改（全局 glob 自动覆盖 `__tests__`） |
| 根级 `tests/setup.ts` | 不动（Vitest 全局 setup 的正确位置） |
| `e2e/` | 不动（Playwright 独立于单测体系） |

## 9. 决策记录

| 决策 | 结论 | 备选与否决理由 |
|---|---|---|
| 测试目录位置 | `packages/<pkg>/__tests__/`（与 src 平级） | `tests/`（与根级 tests/setup.ts 风格更配但弃 Vue 生态惯例）；`src/__tests__/`（测试仍混在 src 树，诉求只完成一半）——用户选定 Vue 官方风格 |
| 内部结构 | 镜像 src 目录树 | 平铺会在文件多时失去对应关系 |
| 与 spec11 排序 | spec11 先完成（事实已发生），本次在新结构上进行 | 并行执行会同时移动同一批测试文件，冲突不可避免 |
| 源码重组力度 | 按需归置两包（vue / markdown） | 全包彻底重组会出现多个一文一目录，且 dev-server 刚被 spec11 重组过 |
| 规则落点 | rules 文件 + CLAUDE.md 引用 | 全写进 CLAUDE.md 会破坏项目既有 rules 拆分模式 |
