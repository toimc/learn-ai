# Mastra 可观测性集成（traces + logging）

- 日期：2026-08-29
- 状态：已批准（对话内逐节确认）
- 范围：packages/dev-server（Studio 线），零库改动

## 背景与目标

dev-server 的 Studio 线（`src/mastra/index.ts`，4111）已有完整 Mastra 实例，但只有旧版 `telemetry: { enabled: true }`（OTel，默认输出控制台，不落盘）。目标是接入 Mastra 官方新版 Observability 系统（`@mastra/observability`），让 Studio 内可直接查看 traces 与 logs，且日志与 trace 自动关联。

**版本事实**（已验证）：已装 `@mastra/core` 1.60.0 的 Mastra 构造器支持 `observability` 选项；`@mastra/observability` peer 要求 `>=1.16.0 <2.0.0`——**core 不升级**，新增 `@mastra/observability@^1.17.4`、`@mastra/loggers@^1.3.0` 两个轻依赖。

### 目标

1. Studio 线 agent 运行 / 工具调用 / workflow step 产生 spans，持久化到本地库文件
2. PinoLogger 控制台输出 + observability 存储双写；日志自动关联 trace/span ID
3. 默认开启（配置了 `MASTRA_MODEL` 即生效），`MASTRA_TELEMETRY=false` 显式关闭（opt-out）
4. 演示埋点：1 个工具（search-docs）+ 1 个 workflow（docs-pipeline）内 `getLogger()` 用法示例

### 非目标

- metrics（需 DuckDB/ClickHouse 原生模块，LibSQL 不支持聚合）
- 网关线（8787 裸 Agent）接入——明确排除
- 外部 OTLP 导出（Langfuse/SigNoz 等）
- `@mastra/core` 升级（锚点 1.60）

## 设计

### 数据流

```
Studio 线 mastra/index.ts (4111)
  └─ new Mastra({
       storage: await MastraCompositeStore ──┬─ default 域 → .temp/dev-server.db        (LibSQL：会话/threads，不动)
       │                                       └─ observability 域 → .temp/observability.duckdb (DuckDB：traces+logs+metrics)
       logger: PinoLogger('dev-server', 'info')
       observability: Observability ── MastraStorageExporter + SensitiveDataFilter
                                          + logging: { enabled: true, level: 'info' }
     })
```

**存储域实施中发现（2026-08-29）**：LibSQL 观测域只支持 traces（`@mastra/libsql` 1.21.x 未实现 `batchCreateLogs`，core 默认实现仅告警丢弃，logs 只剩控制台）。官方 quickstart 的本地推荐组合即 LibSQL 主库 + DuckDB 观测域（`@mastra/duckdb@1.6.3` 实现了 `batchCreateLogs`，peer `>=1.57.0` 兼容 core 1.60，且附带 metrics 聚合能力——Studio 观测图表的数据源）。据此观测域改用 DuckDB，会话域保持 LibSQL 不动。

### 关键决策

1. **composite 分域**：官方推荐观测数据独立 store；删 `observability.duckdb` 即可重置演示数据不伤会话历史；观测数据膨胀不影响主库。观测域选 DuckDB 而非 LibSQL：LibSQL 无 `batchCreateLogs`（logs 不落库），DuckDB 是官方本地推荐且有 metrics 聚合（Studio 观测图表数据源）
2. **SensitiveDataFilter**：span 输出前脱敏（passwords/tokens/keys），兼作安全教学点
3. **opt-out 开关**：`MASTRA_TELEMETRY` 变量名不变（兼容既有 .env），语义从 opt-in 升级为 opt-out
4. **埋点防御式**：工具内 `context?.mastra?` 链式取用，网关线共用工具定义时不可崩
5. **观测栈版本锁（overrides）**：`@mastra/core` 锚 1.60（16 章集成实测基线），`@mastra/loggers@1.2.0`/`@mastra/observability@1.16.6`/`@mastra/duckdb@1.6.3` 经 `pnpm-workspace.yaml` overrides 全局锁死——更高版本依赖 core 1.63+ 的导出（`buildLogRecordData`/`resolveExportedSpanId`），且 caret 重解析曾实际把 mastra CLI 树内 loggers 漂到 1.3.0 撞崩启动
6. **DuckDB 生命周期**：`DuckDBStore.close()` 释放原生写锁（Mastra.shutdown() 自动调用）；dev 热重载若未释放会 "Conflicting lock is held"

## 验收标准

1. 仅配 `MASTRA_MODEL` 启动 `pnpm dev:studio`，与 docs-agent 对话（触发 search_docs）后，Studio Observability 视图出现该次对话 trace（agent + tool spans 层级），logs 可查到埋点日志且关联同一 traceId
2. `.temp/observability.db` 生成；`dev-server.db` 会话历史不受影响
3. `MASTRA_TELEMETRY=false`：Studio 照常启动、无观测数据写入
4. 三绿：`pnpm test` / `pnpm type-check` / `pnpm lint`（worktree 内先 build core）
