# 多模态消息组件需求（图片/附件上传、预览、Lightbox、键位、粘贴拖拽）

> 日期：2026-08-15
> 状态：设计已获用户批准（2026-08-15 会话），方案 B：usePendingFiles composable + 薄组件
> 范围：`packages/vue` 的 prompt-input 复合组件体系；core 包零改动
> 前置交付：Toast 组件（`95e82e7`，本 spec 的校验反馈依赖它）

## 1. 背景与目标

现状盘点（2026-08-15）：

- `prompt-input/` 复合组件已存在（PromptInput/Textarea/Submit/Footer/Tools/Button/Header/Body），Playground 已接入
- PromptInput 已有 `files: Ref<File[]>` provide 状态与 `accept/multiple/maxFiles` props，但**未接线**——Playground 的"上传文件"按钮只是装饰
- `attachment/` 已有 6 个展示组件（Attachment/Attachments/AttachmentPreview/AttachmentInfo/AttachmentRemove/AttachmentEmpty），未被 prompt-input 消费
- core 的 `Message.attachments`、`send(content, attachments?)`、`createUserMessage` 全部就绪
- 缺失：文件选择、预览列表、图片 Lightbox、剪贴板粘贴、拖拽上传、Alt+Enter 发送键位

目标：让用户能通过 **点击图标 / 粘贴 / 拖拽** 三种方式添加图片与附件，在输入框上方看到预览列表，图片可点击放大预览，采用 **Enter 换行、Alt/Cmd+Enter 发送** 的默认键位。

## 2. 已确认的设计决策

| 决策点 | 结论 |
|---|---|
| 作用范围 | 全部做进 prompt-input 复合组件；**InputArea 标记 deprecated**（保留导出，文档引导迁移，不删文件） |
| 图片预览 | **事件优先 + 内置兜底**：emit `preview` 事件，宿主监听则接管；未监听时打开内置 ImageLightbox |
| 发送键位 | **可配置** `sendKey: 'alt-enter' \| 'enter'`，默认 `'alt-enter'`（Enter 换行；Alt+Enter / Meta+Enter 发送）；`'enter'` 保持现状（Enter 发送、Shift+Enter 换行） |
| 发送流程 | **异步上传钩子** `beforeSend(files) => Promise<Attachment[]>`：库内维护 uploading 状态，上传完成后才 emit send |
| 拖拽范围 | 仅 PromptInput 的 wrapper 元素（dragover 高亮、drop 接收） |
| 校验反馈 | emit `error` 事件 + 内置 Toast 提示（Toast 已交付） |

### 3.1 usePendingFiles（状态机核心）

```ts
export interface PendingFile {
  id: string
  file: File
  previewUrl: string      // 图片 objectURL；非图片空串（走图标）
  status: 'ready' | 'uploading' | 'error'
  error?: string
}

export interface UsePendingFilesOptions {
  accept?: string
  maxFiles?: number       // 默认 5
  maxSize?: number        // 单文件字节上限，缺省不限
}

export interface UsePendingFilesReturn {
  pendingFiles: Ref<PendingFile[]>
  isUploading: Ref<boolean>
  addFiles(files: File[] | FileList): { accepted: PendingFile[]; rejected: { file: File; reason: string }[] }
  remove(id: string): void
  clear(): void
  setStatus(id: string, status: PendingFile['status'], error?: string): void
}
```

- 校验顺序：accept 匹配 → maxSize → maxFiles 余量；拒绝项返回原因（供 error 事件与 Toast）
- 图片（`file.type.startsWith('image/')`）在 addFiles 时 `URL.createObjectURL`，**`onScopeDispose` 统一 `revokeObjectURL`**
- 纯逻辑，可脱离组件 Vitest 单测（objectURL 用 `vi.stubGlobal` mock）
- 放 `packages/vue` 而非 core：File/URL 是浏览器 API，core 保持纯 TS

### 3.2 PromptInput 改动

```ts
props 新增：
  sendKey?: 'alt-enter' | 'enter'        // 默认 'alt-enter'
  maxSize?: number
  beforeSend?: (files: File[]) => Promise<Attachment[]>

emit：
  send: [{ text: string; attachments?: Attachment[]; files?: File[] }]
  abort: []
  error: [{ files: File[]; reason: string }]

provide 升级：files: Ref<File[]> → usePendingFiles 实例（pendingFiles/addFiles/remove）
```

提交流程：

```
submit（text 或 pendingFiles 任一非空才可发）
  ├─ 无 beforeSend 或无文件 → emit send { text, files }        // 兼容现状
  └─ 有 beforeSend + 有文件 → 全部标记 uploading（submit 禁用 + Shimmer 进度）
        → await beforeSend(files)
        → 成功：emit send { text, attachments }，清空 pendingFiles
        → 失败：对应文件标记 error（红描边）+ Toast，不 emit send
```

拖拽：`dragover/dragleave/drop` 绑 `__wrapper`；dragover 加高亮类（边框 `--ai-chat-color-input-focus-border`）；drop → `addFiles(e.dataTransfer.files)`。注意 dragleave 在子元素间移动会误触发，需计数器或 `relatedTarget` 判断。

### 3.3 PromptInputTextarea 改动

- `sendKey='alt-enter'`（默认）：Enter 不拦截（原生换行）；`e.altKey || e.metaKey` + Enter → preventDefault + submit
- `sendKey='enter'`：现状逻辑（Enter 发送 / Shift+Enter 换行）
- `@paste`：`clipboardData.files.length > 0` → preventDefault + addFiles；纯文本粘贴不受影响

### 3.4 PromptInputUploadButton

```vue
<PromptInputUploadButton kind="image" />   <!-- accept="image/*"，图片 icon -->
<PromptInputUploadButton kind="file" />    <!-- 通用附件 icon，accept 跟随 PromptInput 的 accept prop -->
```

- 内部隐藏 `<input type="file" multiple>`，click 触发文件选择，change → addFiles
- 样式基于 PromptInputButton（复用其 hover/active/disabled），导出为独立组件

### 3.5 PromptInputAttachments（预览列表）

- 位置：wrapper 顶部、textarea 上方（即"输入框上面"）；空列表 `v-if` 不渲染
- 条目复用 attachment/ 展示组件：`Attachment` + `AttachmentPreview`（图片缩略图）+ `AttachmentRemove`
- 图片缩略图点击 → 触发预览链；`uploading` → Shimmer；`error` → 红描边 + title 显示原因

### 3.6 ImageLightbox（内置兜底预览）

```
图片点击（预览列表或消息气泡）→ emit('preview', { attachments, index })
  → 宿主监听 onPreview？→ 宿主接管
  → 未监听 → 内置 ImageLightbox 打开
```

- Teleport 到 body；`z-index: var(--ai-chat-z-popup)`（tokens.css 新增，值 1000，与 z-toast 同级）
- Esc / 点击遮罩关闭；←/→ 切换同组图片；底部 `index+1 / total`
- 进出场动画走 `--ai-chat-duration-normal` + ease-out，`prefers-reduced-motion` 降级
- 宿主接管判定：`useAttrs().onPreview` 是否存在（Vue 3 emit 即 prop）
- 只展示 `mediaType.startsWith('image/')` 的附件

## 5. 错误处理

| 场景 | 行为 |
|---|---|
| 校验拒绝（accept/maxSize/maxFiles） | addFiles 返回 rejected → PromptInput emit `error` + Toast(type=error)，已 accept 的正常进列表 |
| beforeSend 抛错/reject | 对应文件 status='error' + Toast；不 emit send；用户可移除该文件重试 |
| 粘贴非文件内容 | 不拦截，原生行为 |
| objectURL 泄漏 | onScopeDispose 统一 revoke |

## 8. 验收标准

1. Playground 中：点击图片/附件 icon 可选文件；Cmd+V 粘贴截图、拖拽图片到输入框均可进预览列表
2. 预览列表在输入框上方，图片显示缩略图、文件显示图标+名+大小，均可移除
3. 默认 Enter 换行、Alt/Cmd+Enter 发送；sendKey='enter' 恢复旧行为
4. 点击图片打开内置 Lightbox（Esc 可关、可切换）；宿主监听 preview 时不弹内置
5. 提供 beforeSend 时上传中显示进度态，完成后消息带 attachments
6. 超限文件被拒并有 Toast 提示
7. `corepack pnpm test` / `type-check` / `lint` / docs build 全绿
