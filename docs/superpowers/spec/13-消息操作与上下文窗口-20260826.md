# 消息操作与上下文窗口 需求规格

- 日期：2026-08-26
- 状态：已获用户批准（对话内逐节确认）
- 分支：`feat/message-actions-context-window`（从 `dev` 开 worktree）

## 1. 背景与目标

Playground 消息列表（playground.html）缺少基础消息操作能力：AI 消息的复制/重新生成按钮目前只有图标没有行为；用户消息不可编辑；Provider 无上下文窗口概念，长会话会把全部历史发给模型。本规格补齐三件事：

1. AI 消息：复制（markdown 原文）、重新生成（任意位置，删除该消息及其后续，重发）
2. 用户消息：编辑（覆盖内容 + 删除其后所有回复 + 以新内容重发）
3. 上下文窗口：模型级 `maxContextTokens` 配置，发送前自动截断超窗消息（真实 usage 校准 + 估算兜底）

历史连续性：所有重发路径（send / regenerate / editMessage）均一次性发送完整窗口内历史，不存在分步发送。

## 2. 已确认的关键决策

| 决策点 | 结论 |
|---|---|
| 实现位置 | core 层 API（`useChat` 扩展），Playground 只调 UI |
| 上下文计量 | done 帧 `metadata.usage` 真实值优先，`estimateTokens` 估算兜底 |
| 重新生成范围 | 任意 AI 消息；点击中间消息 = 删除它及其后所有消息再重发 |
| 窗口配置粒度 | 模型级，localStorage 存 `{ [modelId]: number }`，本地 Mock 用 `default` 档 |
| 截断对 UI 的影响 | 不删 `state.messages`，只截断发给 adapter 的数组；UI 显示提示条 |

## 3. core 层（@toimc/core）

### 3.1 类型扩展（`types/index.ts`）

```ts
export interface TokenUsage {
  inputTokens: number
  outputTokens: number
}

export interface ChatOptions {
  // 现有字段不变
  maxContextTokens?: number                  // 上下文窗口（token 数），空/0 = 不截断
  tokenEstimator?: (text: string) => number  // 可注入估算器，默认 estimateTokens
}

export interface ChatState {
  // 现有字段不变
  regenerate: (messageId?: string) => Promise<void>   // 缺省 = 最后一条 assistant
  editMessage: (messageId: string, content: string) => Promise<void>
  truncatedCount: number                            // 响应式；当前发送窗口被截断的消息条数
}
```

线协议约定（`StreamChunk.metadata` 开放结构内）：done 帧 `metadata.usage?: TokenUsage`。不改动 `StreamChunk` 类型本身。

### 3.2 estimateTokens

导出公共函数：CJK 字符（`⺀-鿿豈-﫿＀-￯`）按 1:1，其余按 4 字符 ≈ 1 token，向上取整；空串返回 0。零依赖。

### 3.3 消息 tokenCount 维护

- 每条消息写入 `metadata.tokenCount: number`
- assistant 消息：流结束时有 `done.metadata.usage.outputTokens` 则回填真实值，否则 `estimateTokens(content)`
- user 消息：`send()` 时估算；`editMessage()` 后重算
- 既有消息（initialMessages 无 tokenCount）首次参与窗口计算时按估算补

### 3.4 截断算法

发送前执行：从最新往最旧累加 `tokenCount`，超出 `maxContextTokens` 预算的最旧消息不进发送数组；首条 `system` 角色消息始终保留（其 token 计入预算）。结果同时产出 `truncatedCount`（被排除条数）。

与 `maxHistory` 并存：`maxHistory` 物理删除消息（UI 消失），`maxContextTokens` 虚拟截断（UI 保留、仅影响发送）。两者可同时配置。

### 3.5 useChat 内部共享路径

`requestAssistant()`：push assistant 占位消息 → 截断 → `adapter.sendMessage(窗口内历史)` → `for await` 消费 → done.usage 回填（或估算兜底）→ 错误处理与现有 send 一致。三个公开方法收敛到它：

- `send(content, attachments?)`：现有行为，历史含全部消息
- `regenerate(messageId?)`：定位目标 assistant（缺省最后一条）→ 删除它及其后所有消息 → `requestAssistant()`
- `editMessage(messageId, content)`：覆盖目标 user 消息 content（保留 id/createdAt，重算 tokenCount）→ 删除其后所有消息 → `requestAssistant()`

`isStreaming` 中调用 `regenerate` / `editMessage` 直接拒绝（不改动状态）。`abort` / `clear` 行为不变；`truncatedCount` 在每次请求后更新，`clear` 时归零。

## 4. 服务端链路（usage 产出）

| 链路 | 改动 |
|---|---|
| mock-server（8787） | `packages/mock-server/src/mock-adapter.ts`：chatStream 收尾时计算 usage——inputTokens = 对请求 messages 逐条 `estimateTokens` 求和（服务端复用 core 导出），outputTokens = 剧本输出文本估算；填入 done 帧 `metadata.usage`。gateway 兜底补的 done 帧无 usage（前端估算兜底，无碍） |
| Mastra（4111） | 实现时验证 mastra 流尾 usage 帧格式：能拿到则透传到 done 帧；拿不到则该链路自然回退前端估算 |
| 本地 Mock 剧本 | 无后端，前端估算兜底 |

## 5. Playground UI

- **AI 消息操作区**（接线现有图标）：复制 → `navigator.clipboard.writeText(msg.content)`，成功后图标切换已复制态（i18n `shared.copy/copied`）；重新生成 → `chat.regenerate(msg.id)`
- **用户消息操作区**（新增）：复制 + 编辑 icon
- **编辑态**：新建 `packages/playground/src/components/MessageEditor.vue`——textarea 自动高度，Enter 确认、Shift+Enter 换行、Esc 取消，附「确认/取消」按钮；确认调 `chat.editMessage(msg.id, 新内容)`
- **窗口设置 UI**：模型下拉每项右侧齿轮 icon → popover 输入 maxContextTokens；localStorage key `pg.modelContextTokens` 存 `{ [modelId]: number }`；本地 Mock 无模型概念用 `default` 档；空/0 = 不截断；选中模型的值透传 useChat
- **截断提示**：`truncatedCount > 0` 时消息列表顶部浅色提示条
- **按钮可见性**：沿用 hover `visibility` 显隐惯例；`isStreaming` 中编辑/重新生成禁用、复制可用

## 7. 测试

- **core（Vitest，重点）**：
  - `estimateTokens`：纯中文/纯英文/混合/空串
  - 截断算法：system 保留、恰好等于预算、超预算丢最旧、truncatedCount 正确
  - `regenerate`：缺省最后一条 / 指定中间消息删除后续 / isStreaming 中拒绝
  - `editMessage`：覆盖 + 删后续 + tokenCount 重算 / isStreaming 中拒绝
  - usage 回填：done 带真实值用真实值、不带回退估算
- **mock-server**：done 帧含 usage 的线协议断言
- 纪律：红灯先行（commit body 记录红灯证据）；批量补测用独立 subagent 双盲编写（仅凭类型定义 + 文档）
- UI：Playwright 在 playground.html 手动验证复制/重新生成/编辑/截断提示四场景

## 8. 验收标准

1. AI 消息点击复制，剪贴板为 markdown 原文，图标短暂切换已复制态
2. 任意 AI 消息点击重新生成：该消息及其后所有消息被删，新回复从原位置流式生成，请求含完整前置历史
3. 用户消息点击编辑进入编辑框，确认后原消息被覆盖、其后回复被删、自动以新内容重发
4. 模型下拉可配置 maxContextTokens；超窗时发送请求不包含最旧超窗消息（DevTools Network 验证），UI 顶部出现截断提示
5. mock-server 链路 done 帧带 usage；`pnpm test` / `pnpm type-check` / `pnpm lint` 三绿
