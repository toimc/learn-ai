# 运行时 Provider 注册与真实模型会话 — 需求规格

> 日期：2026-08-22 · 状态：已获用户批准的设计，作为多 subagent 并行开发的接口契约基准
> 前置：10-Mastra接入server服务侧（`registerMastraAgent` / `createMastraModel` / `@toimc/agents/mastra` 已落地）

## 1. 目标

playground 页（`/playground.html`）新增「⚙ 设置 Provider → 注册真实模型 → 页面切换模型会话」能力：

1. 新建 `ProviderSettingsDialog` 库组件（纯 UI 表单，收集 provider 配置）
2. mock-server 新增运行时注册路由（把表单提交的配置注册为带工具的 Mastra Agent 模型）
3. playground 顶栏接入设置按钮 + 模型下拉；选中自定义模型后新会话走真实模型
4. 工具调用（get_weather / get_time）在 thinking 面板内呈现（工具名 + 结果），下接整合回复

链路：浏览器表单 → `POST /api/providers`（apiKey 仅服务端内存）→ `ModelRegistry` 运行时注册 →
`GET /api/models` 可见 → `POST /api/chat {model}` → Mastra Agent（服务端执行工具）→ SSE StreamChunk → 前端呈现。

**零线协议改动**：全部复用既有 `StreamChunk`（thinking/tool_call/tool_result/text/error/done）与按 toolCallId 合并语义。

## 2. 接口契约（并行开发的对齐基准，字段名不可擅改）

### 2.1 `@toimc/vue` — ProviderSettingsDialog

```ts
// packages/vue/src/provider/index.ts 导出
export interface ProviderOption {
  id: string            // 服务端生成的注册 id，如 'custom-1'
  name: string          // 展示名
  provider: string      // 'openai-compat' | 'anthropic'
  model?: string        // 模型名（公开视图可选）
}

export interface ProviderFormPayload {
  name: string          // 必填，展示名
  provider: 'openai-compat' | 'anthropic'  // 必填
  baseURL?: string      // openai-compat 必填（预设自动填、可改）；anthropic 可选（官方端点）
  apiKey: string        // 必填
  model: string         // 必填，模型名，如 'deepseek-chat' / 'claude-sonnet-4-5'
}
```

组件：`packages/vue/src/provider/ProviderSettingsDialog.vue`

- Props：`providers: ProviderOption[]`；`open` 用 `defineModel<boolean>('open')`
- Emits：`create: [payload: ProviderFormPayload]`、`remove: [id: string]`
- 表单行为：
  - 类型单选 `openai-compat`（默认）/ `anthropic`
  - openai-compat 的 baseURL 预设快捷选择：OpenAI `https://api.openai.com/v1`、DeepSeek `https://api.deepseek.com/v1`、GLM `https://open.bigmodel.cn/api/paas/v4`、Kimi `https://api.moonshot.cn/v1`；可自由编辑
  - anthropic 的 baseURL 缺省留空（官方端点），可填自定义
  - apiKey 用 password 型输入框
  - 校验：name/apiKey/model 非空_trim；openai-compat 时 baseURL 非空；不通过时禁用提交并在字段旁给错误文案（走 i18n）
  - 已注册列表区：每项展示 name / provider / model 与「删除」按钮，删除即 emit `remove(id)`（无二次确认弹层，按钮文案即确认语义）
- **纯 UI 纪律**：不 fetch、不读写任何存储；密钥只在 emit 瞬间交宿主
- i18n：文案 key 统一 `provider.*` 命名空间，中英双语同步进 `packages/vue/src/locales/`
- 样式遵守 style-isolation.md：`.ai-chat-` 前缀、`@layer ai-chat-components`、CSS Variables、禁 `!important`/`:root`
- 从 `@toimc/vue` 主入口导出组件与两个类型

### 2.3 mock-server — 运行时注册路由

新文件 `packages/mock-server/src/routes/providers.ts`（Hono 子应用，挂到 `/api/providers`）：

- `POST /api/providers`，body 为 `ProviderFormPayload`
  - 校验失败 → 400 `{ error: string }`
  - 服务端生成递增 id `custom-{n}`（内存计数，进程重启归零）
  - 组装：`createMastraModel({ id, name, description, model, tools: { getTimeTool, getWeatherTool }, memory })`
    - openai-compat：`model = { id: payload.model, url: payload.baseURL, apiKey: payload.apiKey }`
    - anthropic：`model = 'anthropic/' + payload.model`，注册前 `process.env.ANTHROPIC_API_KEY = payload.apiKey`
  - `registry.registerAdapter(id, adapter, info)`；重复注册同名 name 不替换、直接新增新 id
  - 成功 → 201 + `ProviderOption`
- `GET /api/providers` → `{ providers: ProviderOption[] }`（仅运行时注册项，**绝不含 apiKey**）
- `DELETE /api/providers/:id` → 200 `{ ok: true }`；不存在 → 404
- 注册不做上游连通性校验（惰性，首次对话才真连，失败走既有 error chunk）
- 组装逻辑放 `packages/mock-server/src/mastra/register.ts` 新导出 `registerRuntimeProvider(registry, payload): Promise<ProviderOption>`，路由只做参数校验与调用；Memory 复用既有 `defaultMemory()`
- `openapi.ts` 同步三个端点；**apiKey 只存在于服务端内存，不落盘、不进日志、不进任何 GET 响应**

### 2.4 playground — 集成

- `mock/dispatch-adapter.ts`（新）：按当前会话是否带 `model` 字段分发到 mockAdapter（无 model，行为不变）或 sseAdapter（有 model）

- `ThinkingBlock.vue`（@toimc/vue）：增加**默认插槽**，渲染在思考文本之后；不传插槽时视觉与现状完全一致（additive）
- playground i18n：`pg.providerSettings.*` 与 `pg.providerChat.*` 双语文案

## 3. 边界与错误处理

- mock-server 未启动：设置按钮/模型下拉给离线态，不影响本地 mock 演示
- 运行时注册后删除模型：历史会话再发送 → 网关返回错误 → 走既有 error chunk 呈现
- anthropic 注册但浏览器直连不支持的场景不存在（全链路经本地服务端代理，无 CORS 问题）
- 与 env 注册（`MASTRA_MODEL`）并存：env 为启动时注册（id `mastra-agent`），API 为运行时注册（id `custom-*`），同 registry 不冲突
