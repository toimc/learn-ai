# Vercel 发布分支与部署需求规格

- 日期：2026-08-21
- 状态：已实施（部署上线并验证通过，见第 7 节；3.2 节代码块为最初设计，实际形态见第 7 节架构修正）
- 关联计划：`docs/superpowers/plans/07-Vercel发布分支实施计划-20260821.md`

## 1. 背景与目标

GitHub Pages 只能托管静态文件，无法运行 mock-server（Hono Node 进程，核心能力是 `POST /api/chat` 的 SSE 流式推送）。目标：以**独立发布分支**将「VitePress 文档站 + mock server」部署到 Vercel 同域，主线（master/dev）代码零改动。

## 2. 分支模型（`deploy/` 类型约定扩展）

| 项 | 约定 |
|---|---|
| 分支名 | `deploy/vercel` |
| 基点 | master（`990c78d`，含 dev 全部功能） |
| 方向 | 只进不出：永不合回 master/dev |
| 同步 | master 有新内容时 `git merge master` + push，Vercel 自动重新部署 |
| Vercel | Production Branch = `deploy/vercel`，Root Directory = 仓库根 |
| 冲突面 | 仅 3 处 baseUrl 所在文件行（主线几乎不碰） |

`deploy/*` 是 feat/fix/chore 之外的新分支类型（长期部署分支），不适用「合并后删除」铁律。

## 3. 架构

### 3.1 同域部署

```
https://<project>.vercel.app
├─ 静态资源（VitePress 构建产物，packages/docs/.vitepress/dist）
│   ├─ /playground            Playground 页面
│   ├─ /mock-server-demo      SSE 演示
│   └─ /mock-api              Scalar API 文档页
└─ /api/* → Serverless Function
    api/[[...route]].ts = handle(createMockApp())
    POST /api/chat（SSE）/ GET /api/health / /api/models
    /api/conversations / /api/openapi.json
```

前端同源 `fetch('/api/...')`，无跨域、零 Vercel 环境变量。

### 3.2 Vercel 入口（分支新增 2 文件）

```ts
// api/[[...route]].ts —— 可选 catch-all：/api 与 /api/* 都进函数，原始路径保留
import { handle } from 'hono/vercel'
import { createMockApp } from '../packages/mock-server/src/app'

export default handle(createMockApp())
```

```json
// vercel.json
{
  "installCommand": "pnpm install --frozen-lockfile",
  "buildCommand": "pnpm build",
  "outputDirectory": "packages/docs/.vitepress/dist",
  "functions": { "api/[[...route]].ts": { "maxDuration": 60 } }
}
```

- 直接引 mock-server **源码**（Vercel node builder esbuild 打包，无需预构建）；mock-server 的 Node 入口 `index.ts` 零改动
- `maxDuration: 60`（Hobby 上限）：场景脚本含 500ms/token 的弱网手感节奏，默认 10s 会掐断长场景
- app 已有 `.basePath('/api')` + catch-all 保留原始路径，无需 rewrites
- Node runtime（默认）+ Fluid Compute 原生支持 SSE 流式响应

### 3.3 前端接线（分支改 3 处硬编码）

统一模式：`import.meta.env.PROD ? '' : 'http://localhost:8787'`

| 位置 | 改动 |
|---|---|
| `packages/playground/src/mock/sse-adapter.ts:14` | `DEFAULT_BASE_URL` 改环境判断 |
| `packages/playground/src/components/demos/MockServerDemo.vue:35` | `BASE_URL` 同上 |
| `packages/playground/src/components/MockApiPage.vue:9` | `SPEC_URL` 改 `PROD ? '/api/openapi.json' : 'http://localhost:8787/api/openapi.json'` |

- 线上（构建产物 PROD=true）→ 空串 → 同源请求；本地（vite dev PROD=false）→ localhost:8787，行为与现在完全一致
- 该改动对主线无害（本地不变），未来主线可直接 cherry-pick

## 4. 已知限制（记录并接受，不额外开发）

| 限制 | 影响 | 处置 |
|---|---|---|
| 会话失忆 | serverless 实例回收后用户创建的会话消失 | 种子 4 会话始终在；持久化（Vercel KV）超出本次范围 |
| 长场景掐断 | 500ms/token 长脚本若超 60s 流中断 | 线上实测慢速/markdown 场景数秒内完成，远低于上限 |
| 冷启动 | 首次请求慢约 1-2s | 演示场景可接受（实测首个请求约 5s 含跨洋代理往返） |
| openapi servers 硬编码 | `openapi.ts` 的 `servers[0].url` 是 localhost:8787，线上 Scalar 页的 Test Request 按钮会请求访客本机 | 演示瑕疵，主线文件不在 deploy 分支改（控制冲突面）；后续主线动态化后随 merge 带入 |
| 无后缀路由 | VitePress 产物为 `.html` 文件，`/mock-server-demo`（无后缀）在 Vercel 静态路由回落到首页 | 访问需带 `.html` 后缀或后续在 vercel.json 加 trailing 重写 |

## 5. 安全

- Vercel token（7 天有效期）只通过命令行环境变量/参数传递，**禁止写入任何被 git 跟踪的文件**
- 不在库内发真实网络请求的原则不变：部署的 mock-server 本身就是假数据演示服务

## 6. 验收标准

1. 线上 `/api/health` 返回 `{"status":"ok"}`
2. `/api/openapi.json` 可访问，Scalar 文档页（/mock-api）正常加载
3. Playground（/playground）选 SSE 演示发送消息，流式吐字正常
4. 多会话切换：种子 4 会话数据正常
5. 中断按钮工作（流可中止）
6. 本地 `pnpm dev` 行为与现在完全一致（localhost:8787）
7. 单测：新增「PROD 模式默认同源」用例（红灯先行）；全量 `pnpm test` 通过
8. `pnpm build` / `pnpm lint` 通过

### 实施中的架构修正（相对 3.2 节原设计）

原设计的 `api/[[...route]].ts` 源码直挂方式在实际部署中踩了三个 Vercel 运行时的坑，最终形态：

1. **esbuild 预打包**（`scripts/bundle-api.mjs`）：`@vercel/node` 不内联 `api/` 目录外的项目源码（lambda 的 `/var/task` 里只有 `api/` 与 node_modules），跨目录 import 必然 `ERR_MODULE_NOT_FOUND`。改为构建期把入口 + mock-server 源码 + hono 全部 bundle 成自包含单文件 `api/index.js`（gitignore，构建机生成）。
2. **具名 HTTP 方法导出**（`scripts/vercel-api-entry.ts`）：新 Vercel Functions 运行时把 `.js` 的 `default export` 按 Node 风格 `(req, res)` 解释，`handle()` 返回的 Response 被忽略导致 60s 超时。改为 `export const GET/POST/PUT/DELETE/PATCH/OPTIONS/HEAD = handler`。
3. **固定入口 + rewrites**：`[[...route]]` 文件名的 catch-all 语义在路由生成时退化为单段参数（`/api/一段` 通、两段以上平台层 404）。改为 `api/index.js` 固定入口 + `rewrites: /api/(.*) → /api/index`（Hono 官方 Vercel 模板形态）。
4. 根 package.json 补 `hono` 运行时依赖（pnpm 严格布局下 `api/` 上溯解析需要）、`esbuild` devDep。
