本页把 embedding 推理搬回**你的浏览器**：Transformers.js 动态加载 `Xenova/bge-small-zh-v1.5`（q8 量化，约 25MB），对会话库做向量化检索。**零 API 调用、数据不出浏览器、模型缓存后离线可用**——无需启动 dev-server，打开页面即演示。

## 杀手锏场景

顶部的示例查询「**浏览器性能优化**」：会话库里没有任何标题含这六个字——左轨**关键字匹配**（12-03 的 `indexOf` 基线）0 命中；右轨**语义搜索**能命中标题为「聊聊 AI 交互体验」的会话，因为它的首条消息在讨论长列表渲染卡顿。**按字面找 vs 按意思找**，一查便知。

## 检索链路三步

```
📝 描述拼接（标题 + 首条用户消息，截断 200 字）
  → 🧠 端侧向量化（pipeline · pooling mean · normalized）
  → ⚖️ 余弦 Top-5（归一化后余弦退化为点积，内存数组暴力遍历）
```

- **拼接截断**：比单用标题信息量大得多；200 字上限控制单次 embedding 耗时
- **归一化的意义**：`normalized: true` 把向量归一化到单位长度，余弦相似度退化为点积，省一次开方
- **不需要向量库**：会话量级在几百条以内，内存数组暴力遍历点积毫秒级完成（对照：服务端的 docs-agent 用 LibSQLVector，见[向量检索演示](/vector-search-demo)）

向量随索引落 `localStorage`（key `ai-chat-pg:edge-search-vectors`，含模型标识与版本号），**刷新后免重算**；换模型（维度变化）或数据损坏时自动丢弃重建。

## 加载体验三件套 + 降级链

| 手段 | 行为 |
|---|---|
| **懒加载** | 进页面不下模型；首次**聚焦搜索框**才触发（不用搜索的访客不付流量） |
| **进度反馈** | 下载进度条实时百分比（Transformers.js `progress_callback`），有数字的等待比白屏转圈可容忍 |
| **缓存** | 模型文件写进浏览器 **Cache Storage**，第二次访问秒级就绪——只要不清站点数据，只下载一次 |

降级链三级，端侧缺席时**功能不消失，只是变笨一点**：

```
WebGPU（navigator.gpu 存在，GPU 并行）
  → WASM（CPU 计算，慢一些但结果相同）
    → 关键字匹配（模型加载失败时，语义轨回填左轨结果并黄条提示）
```

## 与服务端向量检索的对照

17 章的[向量检索演示](/vector-search-demo)是**服务端**方案（dev-server + Ollama bge-m3 + LibSQLVector），本页是**浏览器端**方案（Transformers.js + bge-small-zh + 内存数组）。选型维度：

| 维度 | 端侧（本页） | 云端/服务端 |
|---|---|---|
| 数据敏感度 | 高——数据不出设备 | 低——内容本来就要发给模型 |
| 成本结构 | 高频轻任务零成本 | 按量计费累积 |
| 延迟 | 缓存后几十毫秒 | 网络往返一两百毫秒起 |
| 模型能力 | embedding/分类等轻模型 | 对话/推理/工具调用 |

典型落地是**混合架构**：检索与路由在端侧，理解与生成在云端。工程细节（设备检测、Cache Storage、降级决策的纯函数拆分）见 `packages/playground/src/semantic/`——`@huggingface/transformers` 仅经动态 `import()` 引入，不进主 chunk。
